# Proposal: 连续同样失败的腿要停止轮换,而不是每 6 小时复活一次

## 事实(数出来的,不是感觉)

`subkimi` 从 **08-20 到 08-25、跨 10 轮 panel**,每一轮都死在同一句话上:

```
error: failed to run prompt: provider managed:kimi-code has no credential configured
```

（`/root/aiwork/logs/*subkimi.log`,10/75 份命中同一串。）

根因很简单:令牌被清空了(凭证文件只剩 `{}`),**要人跑一次 `kimi login` 才会好**。
08-25 业主一问、两分钟就修好了。

## 问题不在"检查不够严",在"重复的信号没有变成一件要做的事"

我第一版判断是「`subkimi:172` 那道 `-e` 前置检查是 fail-open」——**这个判断站不住,已撤回**:
那道检查挡的是"从来没配过",而更严的检查只能把**7 秒失败**变成 0 秒失败,救不了任何东西。

真正的形状是:**`health.tsv` 把所有失败都当成抖动。**
每条腿只记 `状态 + 时间戳`,冷却 6 小时后自动重新可用。
- 429 / 超时 / 额度 → 冷却重试**正是对的**;
- "没登录"这种**要人动手**的 → 冷却一万次也不会好,它只会每 6 小时死一次,循环 6 天。

而每一轮的信号都是同一句 `WARNING: subkimi review failed` —— **它响了 10 次,准确无误,
然后被当成背景噪音**。这是本仓已经记过的老账:**「只报不拦」的免责声明要当待办读**。

⇒ 所以要做的**不是再加一句提示**(提示已经有了),是**让状态会变**。

## 代价评估(诚实:比听起来小)

每轮成本 ≈ **7 秒 + 一次 escalation**,而 escalation 每次都补位成功、预算都满足了 ——
**没有任何一个结论是因为它错的**。唯一真实的损失:
**我们以为有 4 个模型家族可选,实际只有 3 个**,而多样性正是 panel 的全部价值。

## 打算怎么做

1. `health.tsv` 加第 4 列:**连续硬失败次数**(streak)。
2. 只有 **rc≠0** 的状态(`FAIL` / `quota` / `auth`)才 +1;
   🔴 **`PASS` / `DEGRADED` / `INCOMPLETE` 一律清零** ——
   它们都产出了东西。**submimo 今天就是 `INCOMPLETE`**(裁决行没匹配上,而它那份评审写得很好),
   把它算进连续失败会把干活最好的腿踢掉。**这是这一单最容易做错的地方。**
3. streak ≥ 阈值(默认 3,`PANEL_HEALTH_DEAD_STREAK` 可调,0=关掉)⇒
   **停止轮换该腿**(无视冷却),并打印一行响亮的话:连续几轮、最早哪一轮、去看哪个日志、怎么清。
4. 清的办法**不新造命令**:现成的 `PANEL_HEALTH_OVERRIDE=<leg>=healthy` 就能强行放回;
   它一旦跑成功,streak 自动清零。
5. 向后兼容:老的 3 列行照读(缺第 4 列 = 0),不许因为格式变了就崩。

## 会不会造成误报

会,如果第 2 条做错。所以判据里**专门有一条**盯"`INCOMPLETE` 不许计数"。
另外 `quota` 确实会自愈 —— 它连续 3 轮才停轮换,而那行提示会写明"最早一次在什么时候",
额度问题通常几分钟内的 3 轮,人一眼能分辨,强行放回也只要一个环境变量。
