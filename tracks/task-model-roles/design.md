# Design: task-model-roles

第一性检查：角色是本次任务的行为，供应商家族是模型事实，App 是 GitHub 权限；三者不能绑定成常驻分工。旧 App 已按权限分开，无需改变；GitHub 实际推送者已经可靠地存在，不能重复建立作者体系。

已有一次真实 DeepSeek 方案挑战，记录见 design-check.md。接受它指出的未知来源问题；不接受“本地重叠为零便无风险”，因为未知不能算零。后来复核 OpenDesign main 的 collector/authorOf/policy，确认已有账号归属，当前缺陷不需要新协议即可修。

最小方向：authorOf 已知时只排除 author.family；未知时仍排除 policy.builders 的所有可能家族，并保留原人工批准路径。来源生成、全部贡献覆盖及共享 App 的模型认证尚未解决，因此不扩自动放行作者名单。

review-pr 使用一个 owner/name 输入贯穿 API、Git URL、标题和发布；从该目标仓库可信 main 读规则，没有规则则拒绝，不借用 OpenDesign 的项目风险。gh-app-token 在既有配置的仓库范围内收窄一次令牌，并核实实际授权的完整仓库名和权限。缺安装权限时报错，不改 App 配置。

oracle：四家族角色交叉矩阵、high 两家去重、未知/混合来源对照；仓库路由、错误仓库响应、无效参数、精确令牌授权；原规则来源、HEAD、模型冻结测试回归。测试先单独提交，原代码应红。

测试不能证明云平台实际提供接口或宿主 root 已隔离；真实联调与独立审核均为后续验收。不给假数据盖生产认证章。
