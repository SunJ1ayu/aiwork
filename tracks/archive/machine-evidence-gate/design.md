# Design: machine-evidence-gate

- Date: 2026-08-08

## 一、`bin/runlog` —— 让机器自己写下它跑了什么

```
runlog -t <track> [-n <slug>] [--repo <dir>] -- <命令...>
```

行为:

1. 在**跑之前**记下 `commit=<sha7>` 与 `dirty=<yes|no>`
   (`git status --porcelain` 非空即 dirty,**含未跟踪文件** —— 闸① 的教训:
   未跟踪文件在 diff 里是隐形的,所以在这里必须算进"脏")。
   顺序不能反:收据文件本身会把工作树弄脏。
2. 跑命令,输出**同时**流到终端和收据文件(合并 stdout/stderr)。
3. 收据落在 `tracks/<track>/evidence/<YYYYMMDDThhmmssZ>-<NN>-<slug>.txt`
   —— 文件名按字典序排 = 按时间排(规矩5b 靠这个取"最后一份")。
   `<NN>` 是同一秒里的第几份,**两位零填充**:光靠 slug 去重不行 ——
   同一秒依次跑 c、b、a,字典序会排成 a<b<c,和时间序正好反过来。
4. 收据末行是**收据行**,单行、可 grep、字节稳定:

   ```
   runlog: <slug> rc=<n> commit=<sha7> dirty=<yes|no> at=<ISO8601Z> file=<仓内相对路径>
   ```

5. 终端最后打印这一行,附一句「粘进 verify.md」。
6. **退出码原样透传**被跑的命令(否则 runlog 会把红的跑成绿的 —— 那就成了本单要堵的
   那种病本身)。runlog 自己的用法错误用 `64`,且发生在任何命令开跑之前。

## 二、`track-guard` 规矩5 —— 粘过来的数必须是它写的数

对每一份被检查的 `tracks/[archive/]<name>/verify.md`,取同目录 `evidence/*.txt`
里每份文件的最后一行 `runlog: …` 作为该收据的收据行,然后:

| 子条 | 何时查 | 查什么 | 堵住的是 |
|---|---|---|---|
| **5a 一致性** | 每次(同规矩2 的范围) | verify.md 里每一行 `runlog: …`(去掉首尾空白后)必须与某份收据的收据行**逐字节相同** | 手抄抄错 / 凭记忆写数 / 把 `rc=3` 写成「全绿」 |
| **5b 完整性** | 仅归档 | 字典序**最后一份**收据的收据行必须出现在 verify.md 里 | 跑完最后一遍不贴了、只贴早先那份好看的 |
| **5b′ 红的不许藏** | 仅归档 | **每一份 `rc≠0` 的收据**都必须被引用 | 跑砸之后补一条 `-- true`,最后一份就绿了 —— 全程不用动收据文件(一轮四审 M4) |
| **5c 存在性** | 仅归档 | 一份收据都没有 ⇒ verify.md 必须有一行 `- 无机器证据:<理由>` | 干脆不用这个工具 |
| **5d 留痕** | 仅归档 | 每份收据必须已被 git 跟踪或在本次提交里暂存 | 证据只躺在本地、随手一删就没了(闸① 同款盲点) |

设计取舍:

- **5a 只在 verify.md 里出现 `runlog:` 行时才查** ⇒ 仓里现存的 40 多份老 verify.md
  一条都不会误报。没有误报是这道闸能活下来的前提(误报 ⇒ `--no-verify` ⇒ 比没有更糟)。
- **5b/5c/5d 钉在归档**,理由与规矩3 同款:判据是一路补的,中途每次提交都查必然误报;
  「归档 = 宣布做完了」是唯一没有歧义的钉点。
- **5c 给的是显式认账口,不是硬堵**:纯文档 track 本来就没什么可跑。
  但「没有机器证据」从此必须是白纸黑字的一句话,不能是沉默。

## 三、明确不解决的

**防伪不在射程内。** 手改一份收据文件就能骗过这四条。但那是蓄意伪造:
要多改一个文件,而那个文件会出现在 diff 里(闸③ 亲读 diff),
且 5d 保证它必须进 git。这道闸堵的是**顺手四舍五入**,不是造假 ——
说明书里必须这么写,否则下一个读到它的人会高估它,那比没有闸更危险。

**强度只等于它检查的东西**:5a 保证「粘的数=机器写的数」,
不保证「跑的是对的判据」——那是 lane / oracle 的活,别指望这道闸。
