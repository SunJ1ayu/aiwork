# Proposal: worktree-sweep

- Date: 2026-08-11
- Status: selected(用户当场拍板「可以 开一轮做掉吧」)

## 真问题

上一单(`codex-worktree-delegation`)把派活改成"一单一棵独立 worktree",于是**树会攒**。
今天实测:`worktrees/mcp-registry` 从 08-03 挂到 08-11(**8 天**,6.6M),
它对应的那一轮**早就归档了**;design-studio 那边还挂着第二棵(08-07 的基线对照树)。
两棵我都手工查过、确认是净垃圾才收掉的。

上一单给的机制只有一层:收货时**打印**一句回收命令 + 盘点。用户一句话点破它的弱点:

> 「为什么不直接做成 track 一轮走完最后直接收尾删掉树呢」

他是对的,理由是本机反复验证过的教条:**补入口有效,补提醒无效**。
`track archive` 是每一轮的**必经动作**,而"收货时打印一行"要靠我自己看。

## 用户的第二问,以及我的答案

> 「每派一个 codex 执行应该有一个任务 id 这样就能对的上没错吧,还是你有更好的建议」

**id 其实已经有了**(树名 = 任务名+时间戳,分支/回执都跟着它)。缺的是**归属** ——
树不知道自己属于哪一轮。但再往下想一层:

- **"能不能删"不需要归属**,只需要一条判断:**这棵树里有没有别处没有的东西**。
- **归属只在"不能删"的时候才值钱**:干净的扫掉就完了;**留下来那棵**才需要知道
  "这是哪一轮的活、该问谁"。今天我为那棵 8 天的树考古了几分钟,就是这个成本。

⇒ 两层都做,但**分清主次**:安全判据是主,归属是让报告能点名。

## Scope

- in:
  - `track archive` 收尾时清理**属于这一轮**的 worktree:**只删确认干净的**;
    有一棵不干净就**拦住归档**并点名(`--keep-trees` 显式放行)。
  - `delegate-codex --track <name>`:把轮次写进**树的路径**(`worktrees/<track>/<job>`)
    和分支名 —— 磁盘就是账,不另建登记表。
  - 清理用 `git worktree remove` + `git branch -d`(未合并会自己拒),**绝不 `rm -rf`**。
  - 跨仓:树的归属仓从 `<tree>/.git` 里读(design-studio 的树就躺在 aiwork 的 worktrees 下)。
- non-goals:
  - **不做"超过 N 天自动删"**:时间不是安全判据,"有没有别处没有的东西"才是。
  - **不删别的轮次/无主的树**(比如今天那两棵那种手工建的):只**报**,不动手 ——
    我不知道它们的故事,而删错的代价不对称。
  - 不建 registry/manifest/状态机(上一单已驳回:第二份账会和磁盘对不上)。
  - 不改隔离本身的语义,不碰闸①。

## Success criteria

- 一棵**干净且成果已在主线**的树,在 `track archive` 时被自动收掉(树 + 分支),
  而主仓一个字节没动。
- 一棵**有没保存改动**、或**成果没进主线**的树 ⇒ 归档被拦住,报告点名说是哪棵、卡在哪条。
- **不属于这一轮**的树一律不动,只出现在报告里。
- `--track` 给了就按轮次分目录;没给就是今天的老样子(向后兼容)。
- 判据能证明:把任一条安全检查拆掉,判据当场红(变异测试)。
