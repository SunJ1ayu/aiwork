# Design: archive-tree-and-untracked-views

- Change: archive-tree-and-untracked-views
- Status: draft

- 规划双出: 不适用:本单 `impact.factors` 不含 `new_write_surface`(修的是已有闸的
  取树与报错口径),方向不是开放分叉 —— 两个根因我都已在夹具里量到确定的机制
  (收据 `evidence/20260909T065614Z-01-probe-d15-d16.txt`),不花一次规划双出。

## Approach

三处改动,各自对应一个被量到的机制。

### A. 归档复验锁"本次归档那棵树"(D15 核心)

`bin/track-record:validate_review_delivery` 现在用
`git log --no-renames --reverse --diff-filter=A ... | 首行` 回溯树。`--reverse` + 首行
= **最早**那次 add。改成取**最新**那次 add(去掉 `--reverse` 取首行)。
- 单次生命周期:唯一一次 add,行为不变(要有判据当对照组,防止"修成全拦")。
- 两次生命周期(archive → 手工取回 → 再 archive):锁到第二次,内容变了就红。

### B. 归档后再改档案里的交付内容,复验要看得见(D15 后半)

A 只把树钉到"本次归档",**钉住之后仓库继续往前走,这棵树就再也不动了** ——
归档之后有人改 `tracks/archive/<name>/` 下的交付文件,复验依然看不见。
补一条**窄比较**:用同一套投影规则,只算 `tracks/archive/<name>/`(与其 active 前身)
这一棵子树,拿**当前视图**和**钉住那棵树**比;不等就红。
- 为什么不是"把树换成今天的":投影覆盖整仓,换成今天 = 仓里任何无关改动都会让它红。
- 为什么用投影规则而不是裸字节:`verify.md`、`observations/*.json`、runlog 收据本就
  被有意排除(收口记录),裸比会把"归档后补写 verify.md"这种正常动作判红。
- 实现上给 `_review_delivery.delivery_fingerprint` 加一个 `scope="repo"|"track"`,
  只在投影时过滤前缀,**不动**私有 index/object 存储与双扫描稳定性那套机制。

### C. 两视图的语义差要么提前拒绝、要么把真话说出来(D16)

`working` = index + 工作树改动 + **未跟踪文件**;`staged` = 仅 index。
评审腿看的是 working 快照,归档那次 commit 的 hook 校验 staged ⇒ **两者只在
"工作树相对 index 干净且无未跟踪文件"时才相等**。这不是 bug,是这道闸的**前置条件**,
问题是它从没被说出来过。两处修:

1. **`bin/track archive` 前置拒绝**(操作者站的位置,mv 之前):v2 track 归档前,
   若两视图不等,**响亮拒绝并列出差异路径**,一个文件都不动。
2. **BLOCK 消息说真话**:`validate_review_delivery` 失败时,先算另一视图;
   若另一视图正好命中同一轮合格评审 ⇒ 报"评审绑定的是 X 视图、本次校验的是 Y 视图",
   附上造成差异的未跟踪/未暂存路径,**并且不再打印那句"重跑 panel-review"**
   (我实测过:那句话把人送进一个每圈烧一轮 panel 的循环)。
   诊断只改**措辞与出口码之外的信息量**,绝不把 BLOCK 变成 PASS。

## Key trade-offs / risks

- **B 的边界**:归档之后改动仓内**其它**(非本 track)文件,复验仍然看不见。
  纳入它就得放弃"钉住树",代价是无关改动全变误报 —— 不值。**这条边界写成判据钉住**,
  免得下一个人以为它管得更宽。
- **C-1 是新的拒绝路径**:它会在"仓里有未跟踪文件"时拦下归档。这正是本机
  09-09 那次真实阻断,但拒绝必须给得出可执行的下一步(列路径 + 说 `git add` 或清理),
  否则就是把静默 BLOCK 换成响亮 BLOCK,没解决问题。
- **改的是判卷防线本身**:放松一格没有症状。所以每条新行为都要有单独判据 + 红检变异。

## Alternatives considered

- **D16 改成让归档也用 working 视图**:那等于让"没进历史的未跟踪文件"参与授权,
  commit 之后它们不在树里 —— 被授权的和被归档的不是同一份东西。否。
- **D16 改成评审快照排除未跟踪文件**:评审腿物理上看得见工作树(它 reset --hard 到
  含未跟踪的 tree1),指纹排除 = 指纹不再描述"腿看到了什么"。否。
- **D15 改成取"最近一次触碰归档目录的提交"**:那棵树含归档后全仓漂移 ⇒ 无关改动误报。否
  (B 用窄子树比较达到同一目的)。

## Test strategy (oracle)

判据全部进 `tests/test_review_delivery.py`(真 git 夹具,已有 14 条),红检进
`tests/mutation-review-delivery.sh`。**主 agent 亲自写,先 commit 判据再 commit 实现。**

| 编号 | 钉住什么 | 现状 |
|---|---|---|
| T1 | 归档#1 → 取回 → 改交付内容 → 归档#2 ⇒ `--source staged` **红** | 今天是绿(D15) |
| T2 | 单次生命周期归档仍然绿(对照组:防止"修成全拦") | 绿,须保持 |
| T3 | 归档后改档案里的**交付文件**并提交 ⇒ 复验**红** | 今天是绿(D15 后半) |
| T4 | 归档后改档案里的 `verify.md`/observations(收口记录)⇒ **仍绿** | 绿,须保持 |
| T5 | 评审含未跟踪文件时 staged 复验红,**且消息点名真原因、不含那句错药方** | 消息今天是错的(D16) |
| T6 | 有未跟踪文件时 `track archive` **mv 之前**就拒绝,目录一个没动 | 今天先 mv 再在 commit 处炸 |
| T7 | 干净仓 `track archive` 照常成功(对照组) | 绿,须保持 |
| T8 | 两视图语义差在**脏夹具**上被显式钉住(working 含未跟踪、staged 不含) | 只在干净夹具上平凡满足 |

**这个 oracle 能被什么骗过?**

- **最大的一个**:T1~T4 全绿只证明"闸在夹具里咬得动",不证明**本机真实归档路径**
  走的是同一条代码。09-09 那次真实阻断就是两条评审腿都没走到的地方。
  接得住它的只有一件事:**本单自己归档时,那条路必须真的被走一遍**,
  且我要在 verify 里贴出真实 `track archive` + commit hook 的输出,不是夹具输出。
- T5 钉的是操作者面前的文字。外部腿判不了"话说得好不好",但判得了**话是不是假的** ——
  所以断言只钉两件可证伪的事:真原因出现、错药方消失。**不钉措辞**。
- T6 若只断言 rc!=0 会被"先 mv 再回滚"骗过 ⇒ 必须断言**目录还在原位**。
- 红检若只跑"删断言",会漏掉"把新比较写成恒真"这类放松 ⇒ 变异要按**放松一格**造,
  且基线必须先绿、变异后必须红在**被指名的那条判据**上(红在 ERROR 上 = 没红检过)。
