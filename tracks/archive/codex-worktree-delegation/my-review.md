## 我自己找到的问题

**F1(真错,小):`--dry-run` 的回执会误导收货。**
dry-run 不建树,但回执照记 `worktree=<计划路径>`;拿这份回执跑 `--receive` 会说
"隔离树不在了 ⇒ 现场没了",而真相是**它从来没建过**。话术把"没做"说成了"丢了" ——
这正是本机最在意的那类错误信息(报警器指错方向)。修法:回执加 `dry_run`,收货时分开说。

**F2(结构性限制,必须写进文档):隔离隔的是工作树文件,不是 git 对象库和引用。**
worktree 与主仓共享 `.git`(objects/refs)。所以"主工作树逐字节不被碰"这句只对**文件**成立;
腿在树里跑 git 命令**能动到共享的 refs**(建/删分支、写对象)。判据断言的也正是文件面
(主树 status 空 + HEAD 未变),没有断言 refs 面 —— 我不打算把它做成机械闸(那要么禁 git、
要么做 ref 快照对账,两者都超出本单),但**必须如实写进头部注释和 delegate skill**,
不能让"隔离"这两个字被读成比实际更强的保证。威胁模型仍是"手滑/忘了",不是蓄意。

**F3(接受的偏差):卷宗规则的放宽依赖"腿的沙箱 = 那棵树"这个前提。**
`-s workspace-write` 是本工具硬写的,但 `--` 后面的直通参数能覆盖(比如
`-- -s danger-full-access`)。那样腿就能写主仓,而卷宗现在允许落在主仓里 ⇒ 闸① 退回自证。
不是本单引入(直通参数一直能扩权),但本单**把卷宗安全从结构性变成了依赖参数**。
候选修法(未做):isolate 下若直通参数里出现 `-s|--sandbox` 就拒发。记进 backlog。

**F4(老限制,本单没改也没恶化):`--protect ../x` 能穿越出仓。**
哈希会覆盖仓外文件;而 `git status -- ../x` 的报错走 stderr、stdout 为空 ⇒
"判卷路径干净"那道检查会**静默通过**。protect 清单是我自己敲的,不是腿给的,所以危险度低;
但隔离让这份清单更吃重,记进 backlog(runlog 的 track 名越界是同一形状,那条已经修过)。

**F5(接受):撞名自动挪名字 = 我不小心派了两次会静默成功。**
上一版是"撞了就拒发",我自己的判据当场证明它会把连续两发全堵死(同一秒)。
两害相权:不覆盖是硬的,拒发不是。树路径在终端和回执里都印了,可查。
