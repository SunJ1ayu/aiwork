# Proposal: design-before-build

- Date: 2026-09-20
- Status: open

## 真问题(第一性)

- 用户原话:「那你开始修改aiwork工作流吧 遵循第一性原理」;此前指出方案出错会让后续一轮实现与评审白费。
- 目标:在投入实现之前暴露错误方案的关键假设与代价,而不是只在实现后证明符合规格。
- 当前缺口:track/panel/delegate 的入口把独立设计思考局限为「开放架构分叉」;主 agent 把需求明确误当成方案已验证,填 low 后直接实施。设计模板还混有旧的单轴、新写面规则。
- 这次转译:改决策协议和现场入口,复用独立探索、前提证据及现有工具;不能声称靠字段或文件存在性就能判定方案正确。

## Scope / Non-goals

- 修改工作流规范源、track 模板和 convention,并同步到 Claude 实际读取的位置。
- 明确触发事实、独立输入、最小实验、证据落点、小改动的轻量路径,以及 Jev / 切片的责任边界。
- 不恢复被撤回的 low 非空证据闸,不修改 schema/validator/归档覆盖/风险预算,不安装 Jev skill、不自动调 Jev、不新建调度器。
- 不接管 design-uncertainty-low-needs-reason 的未完成补丁或其他会话正在修改的 OpenDesign 任务。

## 验收边界与轮次预算

- 承诺:各入口不再允许仅凭「需求明确 / 只有一个方案 / 自报 low」跳过应做的独立前提检查;明确先查方案再写判据/实现,且不把所有小修改升级成多模型仪式。
- 承诺:方案记录区分事实、假设与用户目标;独立意见/实验未解决的关键问题不能冒充完成。Jev 不决定降档或放行,切片局部结论不替代完整覆盖。
- 承诺:规范与部署副本逐字节一致;旧 schema/dispatch 契约兼容。
- 不承诺:机器理解方案好坏、模型必能发现隐含假设、已证明降低返工率。
- 方案挑战预算:主 agent + 两个外部不同家族各一次,必要的失败替补单独记账。
- 实质实现评审上限:2 轮,standard=1 家族;第 2 轮核修复。每轮前跑 track preflight。
