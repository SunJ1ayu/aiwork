# 方案协议的预先案例(独立探索返回前写定)

这是主 agent 的人工走读题,不是已证明的收益或模型评测。只查路由是否合理及能否留下可核实证据。

| 场景 | 实施前必须弄清楚的事 | 预期路线 |
|---|---|---|
| 用户明确说「启动自动更新」;把网络放在工作区前;无实测延迟 | 用户目标是否允许每次启动被挡;断网/慢网下真实到可用时间 | 独立挑战从原始目标出发;最小探针;不能因需求明确或 low 跳过 |
| 统一档案格式要迁移现有数据;主 agent 只想出一种设计 | 失败中断后能否恢复;兼容与回退代价;是否必须迁移 | 一次不同家族挑战 + 真实副本上的最小迁移/回退实验;high impact 的实现评审另算 |
| 局部改按钮错字,现有交互不变 | 文案确实对应现有行为 | 主 agent 直接改/核对;不派规划腿、不要求填大表 |
| 一个边界条件已在旧代码复现,按既有契约局部修复 | 修复不改变契约,回归是否覆盖相邻路径 | 主 agent 判据先行后修复;风险档决定实现评审,不因 high impact 就自动多模型规划 |
| 将原本可离线使用的功能改为启动前访问外部服务;接口文档齐全 | 接口可用不等于用户体验可接受;不可用时是否仍可完成目标 | 独立挑战 + 故障探针;不能仅凭外部文档把方向判为已验证 |
| 方案挑战发现关键前提但短期无法实验,模型又给了好评 | 哪个结论仍未知,是否有不依赖它的缩小方案 | 记录未解决项;继续收证/调整方案,不能把一次调用写成前提已解决 |
| 所有模型都不可用,Jev 却给低分 | 模型失败是缺证据,低分不消除原来的触发事实 | 可继续做独立于方案的事实探针;不假装完成挑战或悄悄降档 |
| 多模块改动按目录切片,老测试脚本没改却受影响 | 变更和关联契约分别由谁审,是否存在片外责任缺口 | 主 agent 补责任映射;整体腿仍独立看全局,切片不换取旧归档覆盖 |

走读通过只能证明文字路线覆盖这些例子。后续自然任务必须记录实际触发事实、前置耗时、
发现的前提及其核实、是否避免/仍发生设计返工。没有事实标签,不报准确率、误报率或节省比例。
