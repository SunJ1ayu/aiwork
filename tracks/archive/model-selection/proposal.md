# Proposal: model-selection

- Date: 2026-09-20
- 用户原话:「应该让主裁大模型自己看发散池和审查池里有什么，然后自己选择，不应该固定」「我要用两个cursor的模型比如一个grok和池子里的其他模型」「走一下我们最新的aiwork流程开始改」。
- 目标:主裁能查看真实候选及能力/可用性,显式选择本轮成员;一个通道可在同轮使用多个模型。
- 当前事实:普通评审只接受轮换;subcursor 仅一个席位和全局模型;explore 单独硬编码派发名单。

## 范围与验收

统一候选描述与显式选择,review/explore 支持两个独立 Cursor 成员,每个成员独立模型/日志/结果。
能力、调用通道、实际模型、计费共享关系与覆盖资格分别表达;未知额度不可写成充足。
保留旧命令兼容,默认轮换作为旧入口回退;新工作流要求主裁先看候选后选人。
现有只读隔离、同轮同subject覆盖、风险预算、身份验证、历史结果读取不得放松。
不做自动最佳模型排名、计费爬虫、公司关系推断独立性、任意命令插件或重新设计整个执行框架。

## 预算

设计阶段先一次不同家族且能读仓库的独立挑战;有具体未解分歧再追加一次。
实现风险 high(评审控制面),评审最多2轮实质轮;全池控制面审查使用现有可信工具,不可只靠新调度器自证。
基础设施失败重试单记;额度/鉴权失败不算完成证据。主 agent 写全部oracle并先单独提交。
