### 问题 3:默认走聊天腿的副作用 —— PANEL_INCLUDE HINT 常亮,够不够?

**结论:够,且是正确的设计选择。**

HINT 的触发条件(`bin/panel-review` 第 207-210 行):

```bash
if [[ -z "${PANEL_INCLUDE:-}" ]] \
   && { [[ "$(basename "$GLM_CMD")" == "subglm" ]] || [[ "$(basename "$DEEPSEEK_CMD")" == "subdeepseek" ]]; }; then
  echo "  HINT: chat leg in play and PANEL_INCLUDE is empty — it only sees the incremental diff."
```

改前:默认 `GLM_LEG=off` → `GLM_CMD=""` → `basename ""` = `""` ≠ `"subglm"` → HINT 不亮(除非显式设 chat)
改后:默认 `GLM_LEG=chat` → `GLM_CMD="$BIN/subglm"` → `basename` = `"subglm"` → **HINT 默认亮**

代码注释明确承认了这个代价(第 122-123 行):
```
# 代价要认:聊天腿看不见仓库,只看得见 diff ⇒ **派它时记得带 PANEL_INCLUDE**
# (下面第 207 行那条 HINT 就是干这个的,默认走 chat 之后它会常亮)。
```

这够不够?够,理由:

1. **HINT 是 nudge,不是 block** —— 这是 panel-review 的设计契约("the arbiter decides")。把它升级成硬拦会改变契约,且存在合理场景不需要 PANEL_INCLUDE(diff 本身已足够时)。
2. **HINT 文本可操作** —— 它直接告诉用户该传什么:`PANEL_INCLUDE="tests/test_x.py tests/e2e/y.mjs"`,以及为什么:`it only sees the incremental diff`。
3. **常亮不是噪音** —— 它只在"有聊天腿在跑 + PANEL_INCLUDE 为空"时亮;一旦传了 PANEL_INCLUDE 就灭。
4. **替代方案更差** —— 默认走 agent 在这个后端上会每轮 400(注释里实测三档:无工具 200 / Anthropic 形状工具 400 / OpenAI 形状工具 200),看起来在跑其实每次都死,比常亮一个 HINT 坏得多。
