# 我自己那一遍(主 agent,先于任何腿的输出落盘)

## F1(MEDIUM,自述撒谎):日志头印的 base_url 不是实际用的那个

`bin/subagent` 的日志头打 `base_url: $BASE_URL`,而 opencode 这条路根本不用 `$BASE_URL`
(它用的是 `$OC_BASE_URL` = `.../zen/go/v1`)。实跑日志里印的是
`base_url: https://opencode.ai/zen/go` —— **那是 claude 底座的休眠值**。

这正是本机反复吃亏的形状:自述和实际对不上,而且它出现在**取证材料**里 ——
以后有人拿这份日志排查"打的是哪个端点",会被它带偏。
修:按底座印真正在用的那个;并加一条断言钉住(日志头必须印 OC_BASE_URL)。

## F2(MEDIUM,休眠配置看起来像活的):供应商表里 zhipu 那格留着三个 claude 专用值

`DEFAULT_BASE_URL` / `AUTH_ENV` / `DEFAULT_MODEL` 现在对 GLM 腿**都不再生效**
(它走 opencode 分支)。我给 `AUTH_ENV` 写了"只在 claude 底座下有意义"的注释,
但 `DEFAULT_BASE_URL` 没写,`DEFAULT_MODEL` 也没写。
判断:**留着是对的**(将来切回 claude 底座要用),但**每一个都得当场说明它是休眠的** ——
否则下一个人会照着改它然后发现"改了没反应",那是最耗时的一类 bug。

## F3(LOW,但值得记):首次跑会在隔离 home 里下 156M 东西

`~/.cache/aiwork/opencode-review-home` 首跑下载运行时/模型表,实测 >10 分钟没跑完。
影响:panel 四审第一次带这条腿会明显变慢;而且这发生在**判据之外**,谁都不会预期。
不算 bug,但要写进文档,并且**不能让它发生在判据里**(判据有兜底桩,已挡住)。

## F4(工艺,我自己犯的):我把真 key 打进了收据文件

第一次真跑我把 `ZHIPU_API_KEY=sk-...` 写在命令行上,而 `runlog` 会原样记录命令 ⇒
真 key 进了 evidence 文件,而那是要入库的。已删除并全仓+git 历史确认没扩散。
**规矩**:secret 不许出现在会被收据工具记录的命令行上;让腿自己去读 auth 文件。
判据侧已有 V26 ⑤(仓内不许有 key 形状字符串)兜底,但它只在提交后才会响 ——
真正该改的是我的习惯。
