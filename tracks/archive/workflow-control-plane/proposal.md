# Proposal: workflow-control-plane

- Date: 2026-08-20
- Status: open

## Goal

把 aiwork 从“固定四审 + 多份会漂移的说明书”收敛为一套低成本、可追溯的控制面：

1. 高风险改动默认由主 Agent 加两条健康、不同模型家族的评审腿复核，冲突或失效才升级；
2. CLAUDE、skills、README 的规范有唯一版本源，并能机械发现部署副本漂移；
3. 关键工具 commit 真正绑定到具体 track，`ro-repo-exec` 不再漏出保护面；
4. 归档不会默认删除 worktree 中唯一的 ignored 产物；
5. 最终机器证据绑定被测代码状态，但复用原本最后一次测试，不新增一轮模型或测试调用。

## Motivation

现有工作流的职责分离、隔离和判据体系已经成立，问题转向控制面自身：实现与说明书多处
不一致，固定四审在 2 核 / 2GB 服务器上制造长尾且浪费额度，`runlog` 的多数收据只记录
`dirty=yes`，而归档和 track 守卫仍有可导致误删或错误归属的边界。继续增加评审腿或自由
填空不会解决这些问题，需要收紧“规范—守卫—证据”的绑定，同时降低常规评审成本。

## 真问题(第一性)

- 用户原话:「不一定每一轮都需要四审通过」「如果是这样我感觉得换成随机二审就可以，
  这样额度也更节省一点」「可以你开始吧」。
- 真正要解决的是:在不削弱主 Agent 最终责任的前提下，减少无效并发和额度消耗，并让工作流
  自身的规范、证据和危险动作可信。
- 我在这中间翻译了什么:不采用“纯随机抽两条”，而采用“健康池 + 不同家族 + 轮换二审 +
  条件升级”；不把 final evidence 翻译成额外再跑一遍，而是给原本最后一遍增加身份记录。

## Scope

- in: 评审 lane 与 panel 选择/花名册语义
- in: track 绑定、judging-surface 名单和 worktree 归档安全
- in: runlog 最终证据身份与秘密泄漏防线
- in: CLAUDE / skills / README 的唯一规范源、同步和漂移判据
- in: 已知实现—文档漂移修复

## Non-goals

- 不增加新的模型供应商或第五条常驻评审腿
- 不要求所有可用腿全票通过，最终裁决仍只属于主 Agent
- 不为 final evidence 额外增加一次测试或模型调用
- 不清理现有 `logs/`、`out/`、worktrees 或 `/root/.claude` 的用户未提交内容
- 不重写历史 track；只让新流程向前生效
