# Design: no-egress-judging

- Change: no-egress-judging
- Status: done

- 规划双出: 不适用 —— 不是新写面,是给现有判据面加一条**收紧**的不变量;
  方向空间小(见 Alternatives),且已用实测把可行性钉死,不是开放分叉。

## Approach

**不变量(唯一一句):跑判据的进程,没有外网出口。**

实现 = **套件自举进网络命名空间**:每个 `tests/` 判据套件启动的第一件事,
把自己 `exec` 进一个 `unshare -n` 的网络命名空间(`lo` 拉起来),然后才跑用例。

一份共享件 `tests/_no-egress.sh`(bash)+ `tests/_no_egress.py`(python),
套件第一行引入。四个性质:

1. **fail-closed**:`unshare` 不可用 / 隔离没生效 ⇒ **拒跑并说明**,绝不静默继续。
   (V23⑤ 那条教训:我下沉共享件时顺手加过一个 fail-open,重构悄悄把检查改松了。)
2. **不靠环境变量判"已隔离"**:比 `readlink /proc/self/ns/net` 与 `/proc/1/ns/net`,
   两者相同 ⇒ 还在主命名空间 ⇒ 必须自举。
   (V24 刚教训过:`export` 一个环境变量 = 零成本、不留痕的后门。
   环境变量只用来打断"试过一次仍未隔离"的死循环,**不用来判定是否已隔离**。)
3. **每次跑都实测出口**,不是"相信 unshare 有效":进 ns 后主动 connect 一次
   `1.1.1.1:443`,连得上 ⇒ 立刻硬红退出。netns 里是立即 `ENETUNREACH`,零成本。
4. **loopback 必须通**:全部套件的桩服务器都在 `127.0.0.1` 上(已 grep 全仓确认,
   唯一的网络用法就是它),所以 `ip link set lo up`。

**防"下一份考卷忘了加"**:`tests/test-no-egress.sh` 机械扫描
**`tests/` 的命名约定 ∪ 总跑 `SUITES` 里点名的路径**(08-10 四审 subdeepseek:
只扫 glob 的话,往 SUITES 里加一个不叫 `test-*` 的判据,两条覆盖闸完全看不见),
少一个带守卫的就**硬红**。它自己被总跑的孤儿闸强制收进 `SUITES`。
—— 这条和 SUITES 孤儿闸是同一形状:靠"记得加"就等于没有闸。

## Key trade-offs / risks

- **为什么不在总跑入口统一包一层 `unshare`(那样只改一个文件)**:
  手跑单个套件(开发时天天干)就绕过去了 —— 08-04 体检那条「守卫要守对门」的同一个坑。
  守卫必须待在**被守的东西里**,才能同时覆盖总跑 / 手跑 / cron 三条路。
- **风险:某个套件将来真的需要外网** ⇒ 它会红。这是**故意的**:
  总跑脚本头部的契约本来就写着「只跑桩/离线套件,不做真供应商探活(不烧额度)」——
  本单是把这句已经写死的契约**变成真的**,不是新加约束。
- **风险:`unshare -n` 依赖 root / 内核支持**。本机是 root,已实测通过;
  换机器不可用时是 fail-closed(拒跑),不会静默退化成"照旧连网"。
- 进程多一次 `exec`,退出码由 `exec` 天然透传,stdin/stdout/参数不变。

## Alternatives considered

- **给 V23/V24 塞假的 `kimi`/`mimo`/`claude` 命令** —— 否决:只堵今天这两处,
  靠人记得给下一处补,正是用户说的"屎山"。
- **给判据进程一个假 PATH(把 `sub*` 换成空壳)** —— 否决:判据要考的**正是真脚本**,
  换掉被考对象等于把考卷改成自己能过。而且新工具名一出现就漏。
- **在 `sub*` 各腿里加"判据模式"开关** —— 否决:又是一个环境变量后门(V24 刚封过),
  且强度只等于"每条腿都记得查"。
- **网络层是唯一正确的层级**:无论哪个工具、哪条新路径、谁写的新考卷,
  出口只有一个,堵它一次就全覆盖。

## Test strategy (oracle)

`tests/test-no-egress.sh`(主 agent 拥有):

- N1 **真的没出口**:在守卫下起一个探针,连 `1.1.1.1:443` / DNS 解析 **必须失败**。
- N2 **loopback 仍通**:守卫下的桩 HTTP 服务器必须能被自己连上(否则全部现有套件报废)。
- N3 **覆盖完备**:`tests/` 下每个 `test-*` / `test_*` 都带守卫,少一个硬红。
- N4 **fail-closed**:`unshare` 不可用(假 PATH 里放个 `exit 1` 的 unshare)⇒ 拒跑 +
  说明原因;**不许**静默往下跑。
- N5 **环境变量不是后门**:光 `export` 那个标记、人还在主命名空间 ⇒ 仍然拒跑。
- N6 **不自举死循环**:守卫在已隔离的 ns 里再引入一次,不再 exec,正常返回。
- N7 **透传**:守卫下脚本的退出码、参数、stdout 原样(不吞、不改)。
- N8 **回归**:V23/V24 在守卫下仍然**考得出闸**。
  **不写进 `test-no-egress.sh`** —— 它由 `test-review-tooling.sh` 自己证(275/0),
  再加一条判据只会变成同一件事的第二份账。(08-10 四审 submimo 点到这里文档与实现
  对不上,当时我心里知道、没落笔 —— 「同一件事写两处只更新一处」的老毛病。)
  "不再挂 25s" 这半句**判据接不住**(判据不测耗时),靠人跑一遍计时,见 verify 的 F6。

**这个 oracle 能被什么骗过?**

- 用户眼里的成功 = **下周一 08:00 那个 cron 跑完,kimi 额度一点没少**。
  我的断言全绿只证明"判据进程连不出去",接不住的是:
  **别的路径**照样烧钱 —— 例如我在会话里手敲一次 `panel-review`(那是真评审,
  该花钱,不在本单范围),或者某个判据不经 `tests/` 而是被别的脚本内联跑起来。
  真正接得住的证据是**下周一那次 cron 的真实运行记录 + 额度没掉**,
  以及归档前手动跑一次全套并**查 kimi 日志今日调用数不增**(可当场做,已列进 tasks)。
- 另一种骗法:`unshare` 在某次内核/容器变化下"成功"了但其实没隔离 ⇒ 靠 N1 的
  **每次实跑探测**接住,而不是靠一次性验证结论。
