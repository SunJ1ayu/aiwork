# Proposal: delegate-entry-redcheck

- Date: 2026-08-06
- Status: open

## Goal

两个脚本,把两件"有能力但站错位置"的检查搬到成本花掉之前:
`bin/delegate-codex`(派活入口:缺攻题记录 / 缺判卷清单就拒发,并机械化收货闸①)
和 `bin/redcheck`(退回红检:把实现真退回基线再跑 oracle,必须红)。

## Motivation

08-05 `opendesign-turn-id` 一单的实测账:

- 五个真实缺陷里**至少四个不看实现就能发现**(替身缺常量、attach 被弄挂、判据焊死错取舍、
  恒真前置),全部等到 codex 跑完 22 分钟 + 我收货 53 分钟之后才被抓 ——
  用户 08-04 自己命名过这个形状:**有能力的检查站在成本花掉之后**。
- "派活前顺手攻一遍我的 oracle"这条规矩**只住在 track 模板里**,
  `delegate/SKILL.md` 全文 grep `攻|挑穿|漏洞清单` 返回空(已实测)——
  我派活时打开的那本抽屉压根不提这件事;而我在 design.md 里把触发条件后半句抄进括号、
  正文却填"不适用",**一次写在纸上、没人反对的自批降档**。
- 闸① 按 CLAUDE.md 字面跑 `git diff <oracle-commit> -- tests/` 当天**不为空**
  (我自己一笔无关欠账也落在 tests/ 里)⇒ 这道机械闸退化成人工辨认。
- 红检有两种,差一个数量级:20:50 用**手写桩**红检 ⇒ 恒真前置是绿的,洞没露出来;
  22:54 **把实现真退回 611dd49 再 build** ⇒ 才发现那条断言在旧实现上也绿。

## 真问题(第一性)

- 用户原话:「你记录下来全部留到明天再做吧」(08-06 00:20);形状那句是 08-04 的
  「**有能力的检查站在成本花掉之后**」。
- 真正要解决的是:**让"派活那一刻"成为一道过不去就发不出的闸**,而不是又一条要我记得的规矩。
  本机反复验证过:补脚本和入口有效,补字段和约定无效
  (`lane:`/`派给:` 有守卫 ⇒ 七份 verify 一次没空过;`Verdict:` 没守卫 ⇒ 两个月空两次)。
- 我在这中间翻译了什么:把"攻我自己的 oracle"从**一条自评字段**翻译成
  **派活入口的必填参数**;把闸①从"人眼把自己的改动减掉"翻译成**一份在派活时就定好的
  `--protect` 清单**。风险:翻译错了会变成"多两个参数、照样绕过"。

## Scope

- in: `bin/delegate-codex`(派活 + 收货闸①机械版)、`bin/redcheck`(退回红检)、
  两者的判据 `tests/test-delegate-entry.sh`、`delegate/SKILL.md` 指向新入口。

## Non-goals

- **不做成 pre-commit hook**:`派给:` 建 track 就填好了,而攻题要等 oracle 存在之后才做得了
  ⇒ hook 会在两个**合法**时刻各误报一次,守卫第一天就被 `--no-verify` 绕过
  (`track-guard` 规矩3 的注释早写清楚了这个坑)。
- 不碰 `submimo fix`(它已有 `--protect`;这一单只是让 codex 腿用**同一份**清单)。
- 不替换收货闸②闸③(亲跑、亲读 diff 仍由主 agent 做)。
