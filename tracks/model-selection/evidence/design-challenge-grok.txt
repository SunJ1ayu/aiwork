**How it works:**

Verified facts this hangs on:

- Roster freeze is a singleton. `_panel-roster-lib.sh` reads `bin/cursor-model` once, `export`s `CURSOR_MODEL`, then stamps **one** pool row: `subcursor|$_cursor_family|subcursor||PANEL_CURSOR_LEG`. Default file is `cursor-grok-4.6-high`, which `cursor_model_family()` maps to **`xai`** (same family as `subgrok`).
- Normal review rotates **legs**, then skips a second selected leg of the **same family** (`selected_family` in `panel-review`). `--all` still launches both transports; `tests/test_subcursor.py::test_duplicate_families_do_not_fill_budget_or_spare_but_all_runs_both` already nails `grok-4.6` via Cursor + native `subgrok`: budget 2 does not fill, `--all` runs both.
- `--pin-leg` is refused unless `--scoped-review`. Health.tsv is keyed by **leg name**. `panel-explore` hardcodes **one** `subcursor explore` to `<prefix>.subcursor.log`.
- Coverage: `coverage_eligible` for `adapter==subcursor` uses `cursor_model_family(requested)`, requires `family` match, `requested==invoked`, same subject, contract v1, decisive verdict. `summarize_results` / `panel_review_coverage` count **unique families in one `run_id` + subject digest**. Stream decoder records `reported_model: None` and only checks that the init **display name** maps to the same family.
- Archive: `render_roster` walks today’s `PANEL_LEGS_ORDER`, then prints **role legs only if they appear in that run’s `.plan`**. Golden roster is exactly those pool names (`tests/fixtures/panel-roster-format.golden`). Old `.subcursor.state` / `.subcursor.result.json` stay the stable prefix.
