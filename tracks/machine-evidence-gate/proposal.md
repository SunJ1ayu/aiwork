# Proposal: machine-evidence-gate

- Date: 2026-08-08
- 触发:开工清单里最后一条工作流欠账 ——「把**我说的**换成**机器打印的**」。

## 问题

verify.md 的 `## Mechanical checks` 里,判据结果目前是**我打字写进去的**:

```
- [x] tests pass —— 判据全绿,866 通过
```

我可能真跑过,也可能记错、跑了一半、把「跳过」读成「通过」。**从字面上分辨不出来**,
而这正是 08-05 turn_id 那单栽的形状:我写「python 866/0」,听起来完美,实际上
回归用的解释器没装 `mcp` ⇒ **一整块闸被整块 SKIP**,汇总照印 OK。
**汇总会撒谎,细节不会。**

08-08 起我已经在粘机器输出了(anydoc 那单的 `run-all rc=3` 就是),
但**靠的是我自觉** —— 没有任何东西拦着我某天写一句「全绿」就交差,
翻开一份 verify.md 也看不出那行字是机器吐的还是我编的。

## 为什么不能靠评审腿看出来

评审腿看到的跟人看到的是同一行字,它没有时光机。它唯一能做的是自己再跑一遍 ——
那样得到的又是**一段它的自述**,而按本机规矩「执行腿的自述一概不作数」。
等于把我的口供换成它的口供,多绕一个模型、多花一笔钱。
何况腿会挂(智谱欠费关着、Kimi 撞额度、MiMo 超时),**时灵时不灵的检查不叫检查**;
腿是活干完了才上场,而机器输出在我下结论那一刻就产生了;
三个月后回头查,`rc=3` 还在 git 里躺着,某条腿当时的意见早没了。

> 腿堵的是「我判断错了」,机器打印堵的是「我压根没跑」。
> 前者是眼力问题,后者是事实问题 —— 用模型查事实是拿贵的东西干便宜的活。

## 提议

1. 新工具 `bin/runlog`:跑判据时由它代跑,**它**把输出连同
   「哪个 commit / 工作树脏不脏 / 退出码几」写成一份收据文件落进 `tracks/<name>/evidence/`,
   并打印一行**收据行**让我粘进 verify.md。
2. `track-guard` 加**规矩5**:verify.md 里的收据行必须与收据文件**逐字节相同**;
   归档时最后一份收据必须被引用;一份收据都没有就必须显式写明理由。

## 不做

- 不做防伪。手改收据文件仍然可以骗过守卫 —— 但那是**蓄意伪造**(而且会出现在
  diff 里、被闸③看见),不再是「顺手四舍五入」。这道闸堵的是后者,别声称堵前者。
- 不强制任何一条判据必须用 runlog 跑(强制 = 误报 = 被 `--no-verify` 绕过,比没有更糟)。
