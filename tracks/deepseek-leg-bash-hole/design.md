## 第一版为什么被推翻(记在这儿,别再走回去)

第一版立的威胁模型:「评审腿能往被评审的仓里写 ⇒ 能写 tests/ ⇒ **能动判据**」,
于是三条底座腿全部关掉 bash,再由我把 diff 算好喂进提示词。

**业主一句话推翻了它**:评审腿够聪明、任务书里已经交代只审查,这么关是不是限制过头了?
往下追,我自己也答不上那个第一性问题:**评审腿有什么动机改判据?**

- 本机那条硬规矩(弱模型最可能的失败方式是改考卷让自己及格)说的是**执行腿** ——
  它有动机:判据绿 = 自己交付通过。
- **评审腿没有这个动机**:它的产出是一份意见,没人拿判据绿不绿衡量它。
  我把执行腿的威胁模型整个套到了评审腿身上,一整单没人拦(工件链里没有一格问动机)。

而关 bash 的代价是实打实的:今天一天的 bug —— E2BIG(两条腿直接起不来)、
SIGPIPE 静默暴毙、基线打错字静默变瞎、收据把代码挤出窗口、未跟踪文件看不见 ——
**全部长在"关掉能力再自己补能力"这条链上,一条都不会独立存在**。

最狠的一条:**加锁造成的静默失效,比"腿可能写个文件"危险得多**。
08-18 那次四审我以为四条腿在审,实际只有两条跑起来了,而 panel 照常出结论。

## Approach(我这一版)

**检测代替预防。**

1. **panel-review 跑前后各记一次被评审仓的工作树指纹**,变了就响亮报出来。
   - 指纹 = `git status --porcelain` 全文 + `HEAD`(现成的 HEAD 漂移检测只看 HEAD,
     看不见工作树被写)。
   - 报警必须**列出具体变了哪些文件**,不是只说一句"变了"。
   - 横幅写进 **每份腿日志** + roster(照 HEAD 漂移那条的先例:结论会被单独读到,
     那时终端上这行早没了)。
   - **不阻断**(rc 不变):主 agent 在 panel 跑的时候干活是常态,
     一律 rc≠0 会制造大量误报 —— 而**误报和假绿一样坏**,警告变噪音就等于没有。
     处理方式是"列出变化让我一眼判断",不是"拦住"。

2. **保留**:write / edit / task / webfetch / skill 关掉。
   零成本 —— 评审腿读代码本来就不需要这些;`task` 尤其要关(spawn 子代理 = 绕过锁)。

3. **退回**:bash 恢复。腿自己跑 `git diff/log/show`,不再由我喂。
   连带拆掉 `_prompt-budget.sh` 和 V29~V32 那一整套(它们测的是一个被拆掉的机制)。

4. **submimo(panel 第一条腿)**:仍要处置,但按新方向 —— 用自建 agent 关掉
   write/edit/task,**保留 bash**;`fix` 模式的 build 档一个字不动(执行腿写代码是本职)。

## Key trade-offs / risks

- **检测是事后的**:腿已经写完了才发现。接受 —— 写了能看见、能回滚;
  对面是"没动机的误伤",不是"有动机的对手"。
- **误报**:我自己在 panel 期间改文件会触发。靠"列出具体文件"消化,不靠阻断。
- **已知不覆盖**:恶意仓 prompt injection 诱导腿把 key 外发。工作树检测看不见这条。
  但腿必须联网调 API,断网不是选项 ⇒ 这条边界留着,写进 verify,不假装解决了。
- **bash 恢复 = 昨天实测的两条路又开了**(`git diff --output=` 写文件、
  `--no-index` 读仓外)。前者正好被新闸看见;**后者看不见**(读不留痕)——
  这是这次转向真正付出的代价,必须写进 verify,不许含糊过去。

## Alternatives considered

- **维持第一版(全关 bash)**:代价是今天这一串 bug + 静默失效风险,收益是防一个没动机的对手。
- **只靠任务书交代"只审查"**:业主提的。它是**指令级**约束 —— 而本单取证的
  mimo/opencode 的 plan 档正好证明指令级和实际能力会脱节(自称禁编辑、实际全开)。
  所以不能只靠它,但它配上"跑完检测"就够了。
- **bash 白名单(只放行只读 git)**:08-18 已证伪,`--output=`/`--no-index` 挡不住,
  对 git 这么灵活的程序做命令行白名单本身不成立。

## Test strategy (oracle)

V34:panel 跑完必须查工作树。
- 对照组:工作树没变 ⇒ **不许报**(防"永远报警"那种永远绿的闸)。
- 腿在跑的时候写了文件 ⇒ 报,且报警里**点名那个文件**。
- 横幅进每份腿日志 + roster。
- 不阻断:rc 仍按腿的结果(误报会毁掉可信度)。
- 前置锚:stub 腿真的写成了文件(不然是在测空气)。

**这个 oracle 能被什么骗过?**

断言全绿但结果仍然错的样子:**闸只在判据的 stub 场景下有效,真跑时因为
`$REPO_DIR` 不是 git 仓/权限问题而静默跳过**(F6 那种形状)。
接得住它的只有真跑一次 panel 看它报不报 —— 判据里的 stub 撞不出这个。
⇒ 收口必须有一份**真 panel 跑**的收据,并在里面确认工作树检查那几行真的印出来了。

## 规划双出:对差异(08-19,gpt-5.6-sol 独立出的那版)

它那版在 `/root/aiwork-plans/plan-dual-worktree-guard.log`。**它比我这版强**,
而且强的地方全在我"以为理所当然"的位置 —— 正是这道工序设计出来要抓的东西。

### 它抓到我方案的一个致命洞:我的方案不能归因

我的方案是 panel 前后对比 `git status --porcelain`。它指出:**这只能知道"仓变了",
不知道是谁改的**。而主 agent 在 panel 跑的十几分钟里改仓库是常态 ⇒ 误报。
我为这个问题专门设计了"不阻断 + 列出文件让我自己判断" —— **等于把误报当成了不可避免的
成本去消化**,而它的方案(按各腿 CLI 的**进程树**审计写系统调用)**根本不产生这类误报**:
主 agent 不是那些 CLI 的后代进程。

### 三个我完全没想到的点

1. **写事件 ≠ 净差异。** 腿写完又删、改完又恢复、改 `.git`、写 ignored 文件 ——
   我的快照对比**一个都看不见**,而这些恰恰是"想遮掩"时最先发生的形态。
2. **UNKNOWN 必须是第三种状态。** 观察器没武装好/中途死了/输出解析不了 ⇒
   **不许冒充 CLEAN**。我的方案里只有"变了/没变",量具自己坏掉时静默算作没变 ——
   而"量具最安静的时候正是最该响的时候"是本机记过的账。
3. **nonce**:防上一轮的收据冒充本轮。我根本没想到收据会过期这件事。

### 它去读了代码,我没有

`bin/submimo:140` 会在**被评审的仓里**建 `.submimo-task-$$.md`(跑完删)。
⇒ 任何"包住整条 wrapper"的审计都会每轮固定报警,而**固定误报的警告一周内就没人看了**。
它明确要求把 wrapper 自身的基础设施写(任务临时文件、日志重定向、tee)放在审计窗口外,
审计器只包**真正的模型 CLI 那一层**。
我写方案时压根没查过"腿的 wrapper 自己会不会往仓里写"。

### 我们判断一致的地方(互相印证)

- DIRTY **不阻断**。它给的理由比我的更硬:非零退出经常被调用方的 `set -e` 截断,
  反而让人不去读已经生成的日志。
- 保留现有 HEAD 漂移检查:那条回答"树漂没漂",新机制回答"哪条腿亲手写过",两者不可互替。

### 我采纳后的结论

**诊断全采纳,但它是一个独立工程,不塞进这个已经跑偏一天半的 track。**

- 本 track 收口范围缩到:**拆掉 diff 注入那一整套 + 恢复 bash + 关掉零成本的写口
  (write/edit/task/webfetch/skill)+ V33**。
- 写审计**单开 track `repo-write-audit`**,proposal 直接用它这版设计(含它给的 11 个
  判据场景和"永远绿的假闸"清单)。
- **窗口期要说清楚,不许含糊**:拆完之后到写审计上线之前,状态 = 08-18 之前那样
  (腿有 bash、能写仓、没人查)。那个状态已经跑了很久,不是本次新增的风险 ——
  但它现在是**明账**,写在 verify 和新 track 里,不是"以后再说"。
