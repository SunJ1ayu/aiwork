# Design: worktree-sweep

- Change: worktree-sweep
- Status: selected
- lane: **full**(新增一个**会删东西**的写口 —— 针孔再薄也不打折)

## 一句话

**"能不能删"由一条机械判据说了算(树里没有别处没有的东西);"什么时候看"挂在
`track archive` 这个必经动作上;"是谁的"只用来让报告点得出名。**

## 一、安全判据(核心,别的都是围着它转)

一棵树是**净垃圾** ⟺ 下面**两条同时成立**:

1. **树里没有没保存的东西**:`git -C <tree> status --porcelain -uall` 为空;
2. **树的成果已经在主线里**:`git -C <repo> merge-base --is-ancestor <tree的HEAD> <默认分支>`。

两条都成立 = 删掉它不会丢任何别处没有的东西。**任何一条不成立就不许删** ——
理由是不对称:留着的代价是几兆盘,删错的代价是丢掉唯一一份改动。

刻意**不用**的判据:

- **年龄**(挂了几天)——时间跟"里面有没有东西"无关。08-03 那棵挂 8 天是净垃圾,
  而一棵 10 分钟前刚交付、还没合回主线的树,删了就是事故。
- **"track 归档了所以它没用了"**——归档是我对**工件**的判断,不是对**那棵树内容**的判断。

## 二、清理动作

- `git worktree remove <tree>`(**不带 `--force`**)。
  > ⚠️ **2026-08-11 实测纠正**:我原来把这句写成"有残留它自己会拒 = 免费的第二道保险"。
  > 只对了一半 —— git 只对 **modified/untracked** 拒,**被 ignore 的它连着一起删**。
  > 而 modified/untracked 在上面那条干净判据就被拦了 ⇒ **正常流程里 git 那道拒绝够不着**。
  > 它真正的价值是:**干净判据本身哪天被改坏时的兜底**(变异 W1 实测到的正是这一幕)。
  > 所以 `--force` 仍然不许加,但别把它算作一道能观察到的闸。
- 然后 `git branch -d <branch>`(小写 `-d`):**未合并会自己拒**,又一道免费保险。
  分支删不掉不算失败,报一行就行(树已经收了,分支是几十字节)。
- **绝不 `rm -rf`**:上一单已经写死这条(redcheck 那次 `--impl` 指到仓外差点真删,教训在案)。

## 三、挂点:`track archive`

`bin/track archive <name>` 收尾时:

1. 找出**属于这一轮**的树(见「四」);
2. 逐棵跑安全判据;
3. **全干净** ⇒ 收掉,打印收了哪几棵、腾了多少;继续归档;
4. **有一棵不干净** ⇒ **拦住归档**(非零退出),点名说是哪棵、卡在两条判据的哪一条、
   下一步该敲什么命令。`--keep-trees` 显式放行(那时只报不删,也不拦)。
5. **不属于这一轮的树**(别轮的、手工建的、跨仓的)⇒ **只出现在报告里,一律不动**。

为什么是"拦"不是"提醒":`track archive` 已经有先例(规矩 5b 少一份收据就拒绝归档),
而"归档时还有一棵没交代的树"正是那种**我一旦放过就再也不会回头看**的东西。
逃生门留一个显式参数,不留环境变量(环境变量 export 一次就永久生效、不留痕)。

## 四、归属:写进路径,不建账本

`delegate-codex --track <name>` ⇒

- 树:`<worktree根>/<track>/<任务名>-<时间戳>`
- 分支:`delegate/<track>/<任务名>-<时间戳>`

不给 `--track` ⇒ 维持今天的样子(`<worktree根>/<任务名>-<时间戳>`,分支 `delegate/<同名>`),
**向后兼容**;这类树归档时只报不删(没有归属就没有"属于这一轮"可言)。

**为什么是路径而不是登记表**:上一单驳回过 registry/manifest —— 第二份账会和磁盘对不上,
本机在"第二份账"上栽过。路径长在磁盘上,`ls` 就是查询,不会漂移。

**跨仓怎么办**:树的归属仓从 `<tree>/.git` 那行 `gitdir: <repo>/.git/worktrees/<name>` 里读
(design-studio 的树就躺在 aiwork 的 `worktrees/` 下,今天实测)。判据和清理都用**读出来的那个仓**,
不假设"树属于当前仓"。

## 五、Test strategy(oracle)

判据自己造临时仓 + 临时树,不碰真仓。必须覆盖:

- **S1 干净树被收掉**:干净 + HEAD 已在主线 ⇒ 归档时收树 + 收分支,且**主仓一字未动**。
- **S2 有没保存的改动 ⇒ 不许删**:归档被拦、报告点名、**树和里面的文件原封不动**。
- **S3 成果没进主线 ⇒ 不许删**:同上(这条最要命 —— 树里有唯一一份没合的提交)。
- **S4 只删自己这一轮的**:同一个 worktree 根下摆一棵**别轮**的树和一棵**无主**的树,
  归档只收自己的,那两棵原封不动,但要在报告里被**点名**。
- **S5 `--keep-trees`**:一棵脏树 + 显式放行 ⇒ 归档照常完成,树不动,但报告仍点名。
- **S6 跨仓**:树属于**另一个仓**(躺在同一个 worktree 根下)⇒ 判据用它自己的仓判,
  收得掉/收不掉都不影响当前仓。
- **S7 `--track` 的路径与分支**:派活时给了 `--track` ⇒ 树落在 `<根>/<track>/` 下、
  分支带轮次名;**没给** ⇒ 老路径老分支(向后兼容)。
- **S8 不带 `--force`**:构造一个 `git worktree remove` 会拒的情况(树里有未跟踪文件),
  证明我们**没有**偷偷加 `--force` 绕过去 —— 那等于把第二道保险拆了。
- **S9 变异**:把 S1/S2/S3 任一条安全检查拆掉,判据必须红。

## 六、我自己先攻这份题(事前攻题,不等评审)

   这类生成物删了能长回来。要是哪天有人把唯一一份东西塞进被 ignore 的路径……那是另一个病
   (它在主仓里同样会丢),不在本单管辖。**写进文档,不做检查。**
2. **`--is-ancestor` 拿谁当"主线"?** 用那个仓的**默认分支**(`origin/HEAD` 拿不到就退回
   `main`/`master`,再拿不到就**拒绝清理**并说清原因 —— fail closed,不许"猜不出就当它合过了")。
3. **树的 HEAD 是 detached 怎么办?** 照样能 `--is-ancestor`,判据不依赖分支名。
4. **归档时那棵树正在被 codex 写着怎么办?** `status` 会非空 ⇒ 判成不干净 ⇒ 拦住。够了。
5. **报告会不会太吵?** 只在"有树"时打印;一棵都没有就一个字不印(否则每次归档都刷屏,
   刷多了就没人看 —— 误报的守卫活不过一周,唠叨的报告也一样)。
6. **`track archive` 现在有没有别的调用方**(会被我改坏)?实现前先查,`--keep-trees` 之外
   不改任何既有行为。
