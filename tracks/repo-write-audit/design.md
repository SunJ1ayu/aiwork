## 1. 三个候选方向

### A. 写审计(gpt 那版,proposal 已详述)
`strace -ff -yy` 跟踪每条腿的进程树,记对受保护根的成功写,三态收据(CLEAN/DIRTY/UNKNOWN)
+ nonce + 横幅进 stdout/腿日志/roster。

- 优点:按进程树归因 ⇒ **主 agent 并发改仓不误报**(这是它胜过前后快照的关键);
  记写事件不是净差异 ⇒ 写完又删、改 `.git`、写 ignored 文件都抓得到。
- 我的疑虑(**未验**):`strace -ff` 对四条腿 × 十几分钟的输出规模。
  **这台机器 1935MB 内存,而"判据把盘撑满"和"内存不够 ⇒ 判据随机红"都是本机记过的账。**
  一个为了防污染而自己撑爆磁盘的守卫,是拿一种事故换另一种。
- 它本质是**事后**的:写已经发生了,只是有人看见。

### B. 副本工作树(每条腿在自己的 `git worktree` 里评审)
- 优点:写了也污染不到主仓;aiwork 已经有 worktree 基础设施。
- **我自己看出的致命伤**:腿要评的是**未提交的改动**(今天四轮 panel 全是 `dirty=yes`)。
  副本是 checkout 出来的,**不含未提交改动** ⇒ 要么腿评错了东西(假绿的温床),
  要么得同步脏改动(stash/patch/rsync),而那条链自己就会长出一串 bug。
  ⇒ **我倾向不选 B**,除非探针证明同步脏改动是廉价且可验证的。

### C. 只读挂载(mount namespace + `mount --bind -o ro`)
- 腿在自己的 mount namespace 里看到**真实工作树**(含未提交改动,B 的致命伤不存在),
  但整个仓是只读的 ⇒ `git diff --output=` 物理上写不进去。
- **预防,而且不削减任何读能力。**
- 待验的未知(**一条都不许凭推理断言**,08-11 我 design 的前提就被真探针当场证伪过):
  1. 腿的 CLI 在只读仓上会不会崩?它们往仓内写什么?已知至少两处:
     `logs/`(腿日志就在仓内)、`bin/submimo` 会建 `.submimo-task-$$.md`。
     ⇒ 需要把这些路径单独 bind 成可写(白名单式的写口,而不是整仓可写)。
  2. `git` 在只读工作树上跑 `diff/log/show` 会不会因为写不了 `.git/index.lock`
     或刷新不了 index 而失败/变慢?**这条最可能杀死方案 C。**
  3. `unshare -m` 与现有 `setsid --wait` 组合起来,rc 语义还对不对。
- 它照不到:仓外(HOME/`/tmp`)的写 —— 但那本来就不是这一单要防的。

## 2. 我的倾向(探针之前先表态,免得事后合理化)

**倾向 C > A > B**,理由是失败形态的代价:C 的失败是**响亮的**(腿写不了 ⇒ 当场报错),
A 的失败是**安静的**(审计器瞎了 ⇒ 出 UNKNOWN,而 UNKNOWN 会被人当 CLEAN 读),
而本仓反复记账的正是"量具无声瞎掉、而它最安静时正是最该响时"。
但 **C 的三条未知里任何一条为真都可能直接判它死刑**,所以先探针再定案,不先写实现。

若 C 死:退回 A,并且**必须先解决输出规模**(限定跟踪的 syscall 集、只记成功写、
输出落到仓外并设上限),不许让守卫自己成为磁盘事故。

## 2b. 探针结果:C 活下来了,而且是被真机证明的

收据:`evidence/20260819T062919Z-01-probe-readonly-mount.txt`(v1)与
`evidence/20260819T063016Z-01-probe-readonly-mount-v2.txt`(v2,修了探针自己的 bug + 加对照组)。
探针脚本 `probe-readonly.sh` 入库,可重现。

**C.2(最可能判它死刑的那条)—— 证伪了我的担心**:只读工作树上
`git status / diff --stat / log / show / rev-parse / blame / diff HEAD~1` **七条全部 rc=0**,
脏状态(含未跟踪文件)照常显示。**对照组**:同样七条在可写状态下也全 rc=0 ⇒
**差异为零,只读没有削减腿的任何读能力。**

**核心价值被实测**:`git diff --output=<仓内路径> HEAD` 在只读下 **rc=128** ——
就是 08-18 我亲手复现、并因此判定"白名单不成立"的那条绕过,这里被**物理挡死**。
`touch` / 追加已跟踪文件 / `git commit` 同样全部失败。仓外(`/root/`)仍可写 ⇒ 只挡了仓。

**C.1 得到确认(要开写口)**:`logs/`(腿日志就在仓内)和 `bin/submimo` 建的
`.submimo-task-$$.md` 在只读下当场 rc=1。⇒ 见下面的写口白名单。

**一条自伤记在这儿**:v1 探针里 `git blame` 报 rc=128,我差点把它当成"只读削弱了 blame"。
**跑对照组才发现是探针自己挑错了文件**(`CLAUDE.md` 在 `/root/` 不在这个仓里)。
两份收据都留着,v1 那份不删 —— 本仓的账:**红检要跑对照组**,以及**量具自己会坏**。

## 2c. 定案:方案 C,外加三条必须焊死的东西

1. **写口白名单**:namespace 里先把整仓 ro bind,再把 `logs/` 单独 rw bind 盖回来
   (腿日志必须能写)。`.submimo-task-$$.md` **改到 `logs/` 下建**,不在仓根 ——
   仓根一旦开可写,整道防线就没了。
2. **fail-closed**:`unshare -m` 或挂载任何一步失败 ⇒ wrapper **拒跑并非零退出**,
   把理由说清。**绝不许静默降级成"可写地跑"** —— 08-18 两条评审腿把 fail-closed
   判反那件事刚发生过(`env '=key'` rc=0 静默放过 ⇒ 腿活着但永远 401)。
3. **放在各 wrapper 层不放在 panel-review**:腿也会被单独调用(不经 panel),
   放 panel 只护住一条路径。这一条和 gpt 那版的结论一致。

**C 相对 A(strace 审计)的取舍,写明白**:
- C 是**预防**,写根本不会发生 ⇒ 不需要三态收据、nonce、进程树归因那一整套,
  也就没有"审计器自己瞎了却出 CLEAN"的安静失败面(A 最大的风险)。
- C 照不到:仓**外**的写(HOME、邻接仓)。A 也照不到。两者同样不防**有动机的对手**
  (namespace 里的 root 能自己 remount)—— 但本单的对面是**误伤和提示注入**,不是对手,
  这个前提在 proposal 里写着,没变。
- **A 不必立刻做,但也不作废**:C 挡不住"腿把东西写到仓外再由别的进程搬进来"这类,
  真需要归因时 A 仍是唯一答案。记在 `WORKFLOW-DEBT.md`,不塞进这一单。

## 3. Test strategy (oracle)

判据(`tests/test-review-tooling.sh`)要问的五件事:

1. **真的去写,断言写不进去**:假模型 stub 在腿的 namespace 里尝试
   `touch 仓内文件` 和 `git diff --output=`,断言**两者都失败且仓没变**。
   ⇒ 这条是整道防线的正面证明,不许用"grep 到了挂载代码"代替。
2. **读能力一条都没少**:同一 stub 跑 status/diff/log/show/rev-parse/blame,
   断言全部 rc=0(**对照组**:同样命令在没挂载的情况下也全 rc=0 ⇒ 差异只来自只读)。
3. **写口白名单确实开着**:腿能写 `logs/`(否则腿日志写不出来 = 防线把腿弄死了)。
4. **fail-closed**:`unshare` 不可用时 wrapper 拒跑、非零、且理由里点名 ——
   **不许静默降级**。用一个假的 `unshare`(rc≠0)注进 PATH 来测。
5. **反向(红检必须咬得动)**:把 `remount,ro` 那一步拿掉 ⇒ 第 1 条必须当场红。
   这条是变异测试,不是断言。

上面两条现在就定死,来自 gpt 那版明确点名的"永远绿假闸":

- 正向断言必须同时绑定 **本轮 nonce + 精确状态 + 精确肇事腿 + 精确写入路径**,
  并确认假模型自身 rc=0(排除"警告其实来自旁路失败")。
- **对照组是硬要求**:纯读取的一轮必须**精确 CLEAN / 不报**;
  只断言"报了"是假闸(审计器缺失、旁路失败都能让它绿)。

**这个 oracle 能被什么骗过?**

**最危险的形态:只读挂载没生效,而一切看起来完全正常。** 腿照跑、结论照出、
判据里的 stub 场景照绿 —— **"一切正常"正是它失败的样子**。这和 08-18 关掉 bash 那次
是同一个病:失败是安静的。

接得住它的只有两样,都必须做:
- 判据第 4 条(fail-closed):挂不上就**拒跑**,把安静失败改造成响亮失败;
- **一份真 panel 跑的收据**,并在里面确认腿确实在只读下工作过 ——
  判据里的 stub 撞不出这个。⇒ 收口必须有真 panel。

第二个能骗过它的:**判据自己在可写的树上跑**(stub 没进 namespace),
于是"写失败"这条断言其实从没被执行到。⇒ 断言必须**先证明自己进了 namespace**
(前置锚:确认 stub 看到的挂载确实是 ro),否则是在测空气。
