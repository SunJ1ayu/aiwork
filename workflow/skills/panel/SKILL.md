# panel — 多模型评审与发散

两个工具,一个收敛一个发散。**都只负责派发,从不做判断——判断永远在主 agent。**

## 先选对工具(这一步错了,后面全白做)

**实施前先按 4c 的事实选择检查深度**,不能先填 low 再跳过方案检查。方案只有一个,
也可能需要一次独立挑战;两个 panel 都慢且烧 token,不是每次检查都要调用它们。

- **有具体 diff / 存在唯一正确答案**(这段代码对不对、安全不安全、这个说法真不真)
  → **panel-review**(收敛到一个裁决)
- **开放的方案/架构分叉,几个答案都站得住,风险是钻牛角尖**
  → **panel-explore**(保住分歧;自己的方向必须先写下来)
- **方向未分叉,但 4c 命中关键行为/契约/撤回代价** → 一次不同家族的方案挑战;有关键未知先实验。
- **4c 确认为轻量的局部修改** → 主 agent 直接做相应验证,不为此花 panel。
  panel 是第二意见,**永远不能替代主 agent 自己的第一遍工作**。

## 先看候选,再由主裁选人

`panel-candidates --mode review` / `--mode explore` 输出同一目录按能力过滤的候选。
`--discover-cursor` 可查询 Cursor CLI 的可选模型 ID;它不是余额查询或登录证明。
候选含具体模型、通道、可读仓能力、启用状态与历史健康事实;quota 为 null 就是未知。
MiMo 的 explore 只看题面,需要核实源码时选 `reads_repository=true` 的候选。

主裁根据任务与这些事实选择,把理由写进任务的 design/verify,然后显式派发:

```bash
panel-candidates --adapter subcursor --discover-cursor --mode review
panel-review --members submimo,subcursor@composer-2.5 --track NAME --risk high TASK REPO PREFIX
panel-explore --members subcursor@cursor-grok-4.6-high,subcursor@composer-2.5 BRIEF REPO PREFIX
```

Cursor 池可以列出 GPT、Claude、GLM、Grok、Composer 等 CLI 提供的模型,不限于示例。
每个成员冻结模型,同一 Cursor 通道可选多个模型;各自有日志、结果与健康记录。
显式名单不轮换、不自动加人、不回落聊天模型;失败后由主裁决定是否重派并记账。
禁用/不支持模式/冷却中的成员会在调用前拒绝,不会偷换。处理已知健康故障后,
可用 `PANEL_HEALTH_OVERRIDE=subcursor.<model-id>=healthy` 明确重试该模型。
冷却与连败按实际模型记:旧入口的 subcursor 腿也记在 `subcursor.<本轮模型>` 下,与显式成员共用,
同一模型在哪个入口失败,另一个入口都会拒派;不同模型各自冷却,不整通道冷却。
此前留下的无模型 `subcursor` 行追溯不到模型,不再参与判断。
所选家族必须达到 review 的风险下限;同家族两个会话仍只算一份家族覆盖。
家族是粗粒度去重,不是统计独立性证明;公司、账户、额度池也不是家族。
Cursor CLI 可验证请求/调用参数与返回的家族标签,没有返回精确模型 ID 时不能宣称已核实服务端版本。

review/explore 共用选择与会话执行,但 explore 的结果契约为 3,永不提供 review 归档覆盖。
本轮 plan 保存成员与模型,断线后 `panel-roster PREFIX` 按冻结名单重建。
不带 `--members` 的旧入口保留轮换/全池兼容行为;新任务优先使用目录与显式名单。
`--members` 不与 `--all`、`--budget`、切片内部参数混用。

## panel-review — 收敛合议

触发条件同 `submimo review`:非平凡改动、安全/权限/auth/钱/订单/数据一致性/迁移/CI 风险、
不熟悉的代码区、实现后的测试缺口分析。

**顺序至关重要:主 agent 先审、独立审,评审员是对这份自审的复核,不是替代。**先审是为了
反锚定和防偷懒——不能躲在评审员的 "PASS" 后面。

### 0. 先跑 oracle,在派发之前
任务若有客观检查(test / lint / typecheck / 复现命令),**先跑、先记结果**,再去读、
更别说信任任何评审裁决。chat 评审员不能执行代码;07-04 有过三家一起给一份没人跑过的
坏 oracle 判 PASS。用 `PANEL_ORACLE_CMD=<cmd>` 传给 runner:它记录 `ORACLE: <cmd> rc=<N>`
+ 一份 `.oracle.log`,红了会喊但**不阻断**——红 oracle 意味着评审员的 PASS 一文不值,
而这个判断仍然是主 agent 的。

### 1. 主 agent 先审并落盘自己的发现
读真 diff/代码,写下 PASS/BLOCK/NEEDS_MORE_INFO + 具体条目,**在读任何评审报告之前**。
**这道闸在工具里是 DEFAULT-ON,不是要你记得加的 flag**:运行 `panel-review --track NAME TASK REPO PREFIX`
会自动找 `/root/aiwork/tasks/<taskname>-my-review.md`,**找不到就拒绝派发**(或它躺在被审
仓库里也拒——那会经 `collect_untracked` 泄漏)。非约定路径用 `--require-my-review PATH`;
`--no-my-review` 只作为清醒的例外(比如根本没有 diff 可自审的任务)。

**硬规矩:my-review 文件必须放在被审仓库之外。** 引擎会把仓库里每个未跟踪文件内联进评审
prompt,仓内自审 = 喂给评审员 = 反锚定作废。
> ⚠️ **审 aiwork 自己时,约定路径必然用不了**:约定路径是 `/root/aiwork/tasks/<name>-my-review.md`,
> 而被审的仓就是 `/root/aiwork` ⇒ 它必然在仓内 ⇒ 闸拒绝派发,**而它给的建议路径正是它拒绝的那个**。
> 这时只能 `--require-my-review /root/panel-my-reviews/<name>-my-review.md`(仓外),
> 正本仍可留在仓里当工件。08-23 在这上面卡过一次;拒绝时 `rc=1`(fail-closed 是对的,
> 别被 `| tail` 吃掉的 0 骗了)。

### 2. 评审员独立审
实施前先按 **4c** 检查目标到方案的翻译,再记录两个轴:
`impact-risk` 决定实现评审预算(self=0、standard=1、high=2),`design-uncertainty` 记录检查后的判断。
自报 low 不能免掉 4c 命中的检查,high impact 也不自动要求全池规划;两轴不能互相代替。
`panel-review --track NAME --risk self|standard|high TASK_FILE [REPO_DIR] [LOG_PREFIX]` 默认 high=2，
从健康池轮换不同模型家族。失败、降级、没有裁决、NEEDS_MORE_INFO 或裁决冲突时只追加
一个健康 spare；`--all` 才是显式**全池评审**，从唯一花名册派出当前全部已启用且可执行的腿，
留给判卷、沙箱、权限边界或预算评审无法收敛的特殊面。池大小不是契约，增删腿不改这句话。
**连续硬失败的腿会被停止轮换(2026-08-25 起)**:`health.tsv` 每条腿多记一个
**连续硬失败次数**;连续 `PANEL_HEALTH_DEAD_STREAK`(默认 3)轮 rc≠0 ⇒ 那条腿
**不再进入轮换,冷却过了也不放回来**,并在选腿段落打印一行说清:连续几轮、
最早一次在什么时候、去看哪个日志、怎么把它放回来。
> 为什么有它:subkimi 从 08-20 到 08-25 跨 **10 轮 panel** 都死在同一句
> `no credential configured` —— 那是要人跑一次 `kimi login` 才会好的故障,
> 而冷却重试对它永远无效:每 6 小时复活一次、再死一次,循环了 6 天,
> 每轮只留下一句一模一样的 `WARNING`(响了 10 次,被当成背景噪音)。
> **缺的不是提示,是状态会变。**
> 🔴 **只有 rc≠0 才计数**:`INCOMPLETE` / `DEGRADED` 都是 **rc=0**(腿产出了东西,
> 只是裁决行没匹配上)—— 把它们算进去就会**把正在干活的腿踢掉**
> (submimo 08-25 当轮就是 INCOMPLETE,而它那份评审是那轮最有价值的两份之一)。
> 判据 V44g/h 专门盯这一条。
> 放回来:`PANEL_HEALTH_OVERRIDE=<leg>=healthy`,**跑成功一次 streak 自动清零**;
> `PANEL_HEALTH_DEAD_STREAK=0` 关掉整个机制(**垃圾值会拒跑,不会静默关掉** ——
> `abc` 和 `08` 都曾是"我以为开着其实关着";现在 fail-closed,rc=64)。
> `--all` **照派全池里的死腿,但那行提示照打** —— 派它和告诉我它是死的不矛盾,
> 而全池评审恰恰是最该知道“实际健康池已经缩水”的场合。
>
> **计的是"连续 rc≠0"的次数,不看错误是不是同一种**(不做错误文本分类:猜错就是误报)。
> 所以提示写的是「连续 N 轮 rc≠0(最近一次:X)」,不会断言"都以 X 失败"。
>
> 🔴 **一个冷却窗口里的连发失败只算一次**(2026-08-25 第二轮评审补的)。

> 而 `--all` 绕过冷却、计数却照加,那句话在 `--all` 路径上整个是假的:

**`--all` 会无视健康池的冷却**(选腿处显式跳过 healthy 判断)：冷却中的已启用腿照派不误，
所以刚炸过一轮之后仍能立刻全池评审——代价是明知会失败的腿也会占一份等待时间。

`--track` 绑定 typed track 时，显式 `--budget` 只能增加证据，不能低于 self/standard/high 的
0/1/2 机械预算；要做无归属实验必须明确 `--no-track`，但无归属事件不能满足 typed track 的
PASS 归档。归档会再核对同一次成功 panel、同一 subject digest 下是否有 0/1/2 个由共享
predicate 判定为 coverage-eligible 的不同外部模型家族腿；v1、UNKNOWN/NMI、timeout、降级、
证据不完整、跨 run 拼接和 eligible PASS/BLOCK 冲突均不能补预算。
仓里有 typed active track 时，派发前必须显式给 `--track NAME` 或 `--no-track`；前者会在
任何腿启动前校验 decision 已满足 dispatch 且 `impact.level == --risk`。实际腿、回落降级、
总耗时、rc 与真实可得 usage 在全部腿结束后写回主仓 track 的紧凑 observation；prompt 和
完整日志仍在仓外，不复制进 Git。单事件最多 64 KiB；实际腿数量由当轮花名册派生，
不在 observation schema 里再设一个会漂移的数字上限。
每条实际派出的腿各写各的
`<prefix>.<leg>.log`(默认前缀 `/root/aiwork/logs/panel-<task>-<ts>`)。一条腿失败不阻断
其他腿;只有所有实际派出的腿都失败才非零退出。主自审必须在派发前已落盘，DEFAULT-ON
闸会机械检查；不能为了省等待把顺序倒过来。

  > (先派发、后落工件 —— 这才是那句"正确节奏"的完整含义)。这条管**初审**;复审轮核验上一轮修复清单,
  > 处置表先落盘是 4b ② 的要求,复审腿读到它是预期内的,不算泄漏。
  > 做不到就**如实记账**:泄漏了什么、影响多大。那比在 verify 里写"已反锚定"强。
  > > 上面这段 08-24 第一版写的是「引擎内联整份 diff,所以 diff 区间里任何一版都会进
  > > prompt」—— 那是我从"两轮都报 leak"**反推**出来的,没读源码,**推论写成了事实**
  > > (同一天同一单里我还因此给出一条假药方:把 diff base 往后挪)。是 panel 一条腿
  > > 去读 `bin/panel-review`/`bin/submimo-review` 才揪回来。机械钉子:
  > > `tests/test-review-tooling.sh` V22b(树上就够得着)+ V22d(默认不自动设 diff base)。

### 3. 与自己那份逐条对账
他们是顾问,不是投票人;**主 agent 是唯一仲裁者。** 每条:
- **他们标了、我漏了 → 往死里查**(这是 panel 的主要价值:暴露我的盲点/假阴性)
- **我标了、他们没标 → 依然成立**,他们的沉默不是放行
- **他们标了但错 → 驳回**,用我自己对代码的理解

**每个接受/驳回都必须给依据**(如"已核 `file:line`,属实" / "已查 `file:line`,不成立")。
禁止"看报告都说没问题"——这种偷懒正是本协议要防的。

### 4. 出一个合并裁决
PASS / BLOCK / NEEDS_MORE_INFO + 存活的发现。**绝不能只凭评审员的说法定案,绝不能把他们
的结论取平均,绝不能因为一致 PASS 就降低自己的标准**——共同假阴性正是 panel 抓不到的失败
形态,多加一条腿也堵不上。主 agent 独立的、代码级验证过的判断压过所有腿。

### 4b. 收到报告之后:核实 → 处置 → 修复清单 → 复审或结束(本节是唯一权威)

业主 2026-09-16 两次拍板。第一次:「查更新被限流」跑了**八轮**外审,4~8 轮审的是我自己的判据措辞,
当天烧光 Kimi 与 GLM 额度。第二次(同日晚):「审查之后有问题修完会再审查然后就一直循环下去了」
「怎么一单接一单」「没完没了啊」—— 旧规矩③「超出的进下一单」**管住了轮数、没管住单数**
(09-15~16 e2e 卫生账连开两单、第三单差点又开);另一半是收尾问题发现得太晚
(design-studio `opendesign-e2e-guard-followup` 第 1 轮 PASS 后,归档闸才拦下 design.md 一行 `/tmp/…`,
补一个标注作废绑定,白跑第 2 轮)。没有哪一轮当时看起来是错的 —— 每一轮都只是"再确认一下"。

**顺序,不许跳步:**

**① 派任何一轮之前:`track preflight <name>`。** BLOCK 先修 —— 尤其落在非豁免文件上的,
修完再派,这一轮绑定的就是最终内容。PENDING 是正常的(还没评审/仲裁/写收尾记录)。
预检通过 ≠ 可归档,它不留任何标记,归档时全部检查照样重跑。

**② 逐条核实**(上面第 3 步),**然后先处置、后动手**。每条发现在 `tracks/<t>/verify.md` 的发现表占一行:
触发条件与影响 / 核实证据 / 处置 / 理由。处置四选一:

- **本单必须修**:本次验收不成立;**本次引入的回归**;安全·权限·数据一致性风险;
  关键验证证明不了本次承诺(含考卷假绿)。
- **延期**:成立、有价值、不阻断本次交付。理由栏**必须写「它在业主/下一个使用者那边会长成什么样」**
  (说不出来 ⇒ 它本来就不该占一轮;说得出来且真会硌到人 ⇒ 回头看是不是该归「必须修」)。
  延期 = 留在归档的 verify.md 里,**不自动开新单,也不继续施工**。开单要业主说开,或它后来真的硌到人。
- **驳回**:代码/复现/反证核实不成立,写依据。
- **尚未核实**:如实挂着,不许冒充驳回,也不许把猜测自动升级成修复项;高影响的未核实项没解除,本单保持未完成。

判准两句,专治"一单接一单":
- 「测试证明不了**当前**承诺」要处理;「测试挡不住**任意未来**的错误实现」**不自动扩大承诺** ⇒ 默认延期。
- 「业主暂时看不见」**不能单独**成为延期安全、数据一致性或真实验证缺口的理由。

> 🔴 为什么处置必须落在 verify.md:自检留在脑子里就等于没有(2026-09-16 评审点名:纯散文自检
> "只要自问自答一句就能过")。而 `verify.md` 在下面的豁免清单里 —— **写它不作废本轮绑定**,落点是免费的。
>
> ⚠️ **和反锚定那一节怎么同时成立**(2026-09-16 本节第一版自相矛盾,track review-convergence-and-preflight F2):
> 反锚定管的是**初审** —— 第 1 轮派发那一刻 verify.md 必须还没写,这条不变。
> **复审轮**的任务就是核验上一轮的修复清单,题面本来就要列出它,verify.md 里的处置表对复审腿是**已知输入**,
> 不算泄漏;所以处置照旧**先落盘、再修、再派复审**,不许为了"干净"把处置表推迟或删掉。
> 复审腿看得到我的处置,换来的是它能直接挑"这条延期站不站得住";要一份不受处置影响的独立意见,只有初审给得了。

**③ 一轮一份修复清单。** 一轮报告去重分类后定一份清单,**一次修完再复审**;不边读边修,不修一条派一轮。

**④ 复审或结束 —— 按开工时写下的轮次预算。**
- 预算写进 proposal(模板有这一格),**开工时**写,不是过程中的判断(09-16 我中途定过一次又破了例)。
  默认 **2 轮实质评审**;腿数不算轮数(high 一轮就是两个家族)。
- 第 2 轮主要核验上一轮修复清单及其影响面;仍允许报新发现,达到「本单必须修」照样处理 ——
  **不许靠缩小题面屏蔽真实缺陷**。
- verify.md 记每一次派发,分开「实质评审」与「基础设施重试」(腿死/额度/超时拿不到合格覆盖)。
  重试不算实质轮,但次数和耗时照记,不许用"重试"名义藏掉。派发次数 ≠ 返工轮数。
- 预算用完:**无真实阻断 + 机械门满足 ⇒ 结束**。有阻断 ⇒ **保持未完成**,缩范围或回头重看方案(见 4c);
  要追加评审,**派发前**先在 verify.md 写明具体阻断、追加目的、新的有限预算 —— 默认不续轮。
- 这是纪律不是闸:不做轮数硬拦截(会误伤正当轮次,误伤一次就被绕过),也不每轮向业主请示。

**「先别改」—— 评审之后想改东西时,先看它落在哪。**
> 🔴 机制要说准,别说大(2026-09-16 第 1 轮评审当场纠正过我一次)。
> `bin/_review_delivery.py` 的交付投影覆盖整个仓库,但**本 track 自己的收尾记录是豁免的**:
> `verify.md`(整份 skip)、`observations/*.json`(skip)、`evidence/` 里的 runlog 收据(skip)、
> `decision.json` 的 `outcome.verdict`(归一化成 null)、`tasks.md` 的勾选位(归一化)。
> **除此之外**动任何文件(包括判据里一句注释、任何未跟踪文件)指纹就变,归档闸按 subject
> digest 核覆盖时就不认那次 panel。
> ⇒ **窄第三条路**:措辞类修正**只落在上面那份豁免清单里**的,就地改、不作废绑定、不花一轮
> (这不是放宽射程,射程一个字没动,是用它本来就豁免的那部分)。
> 落在别处的:**先别改**;它若只是延期项,就留在 verify.md 里,不自动变成下一单。
> "改了但免审"做不成 —— 要么归档被挡,要么我去放宽指纹射程,**后者就是"改考卷让自己及格"的体面版本**。
> 已经改了才想起这条时,只有两个选项:**回退那次改动**,或认了、重跑一轮(算进预算,写进轮次记录)。别假装没发生。

**收尾决定 ≠ 归档资格。** 延期、驳回写得再有理,也不会让旧覆盖重新有效;
不许伪造 PASS、降 risk、改 observation 来过闸。两件事分开检查。

**读数(机器当面给的,不用我记住)**:`panel-review` 绑定 `--track` 时会在派活当场打印
「这是第几轮 + 自上一轮以来 `tests/` / `tracks/` / 其它 各改了几个文件 + 其它桶的文件名」。
⚠️ 那个「第几轮」数的是**已落盘的派发**(基础设施重试也算,控制器没活到收尾的那次不计),**不是**上面 ④ 预算里的实质评审轮 ——
预算用了几轮看 verify.md 的轮次记录;工具在同一处也会印这句提醒。
**"其它=0" 就是「先别改」的触发条件**:已跟踪的产品文件自上一轮没动过,这一轮审的多半是我自己的考卷。
⚠️ 但**「其它=0」≠「上一轮的评审绑定还有效」**:`tests/` 改动与未跟踪文件同样进交付指纹。
读数回答的是"我这一轮在审什么",不是"上一轮还算不算数"。
它只打印、不阻断(硬拦会在正当的第 4 轮误伤,误伤一次就会被绕过去)。
读数说"上一轮的 commit 读不出来"时,意思是上一轮没有腿交卷或那是 0 腿自审轮 —— **没有对比,
不等于没有改动**,这时要自己看 `git log`。

### 4c. 实施前的设计检查(本协议的唯一详细入口)

**先问「方案完全实现,用户目标仍会怎样失败」,再问「实现是否符合方案」。**
09-19 启动更新事故:等待网络、35 秒超时已写进规格,两家实现评审通过,真实使用仍被卡住。
「需求明确」「只想到一种做法」「design-uncertainty=low」都不能证明目标到机制的翻译正确。

**① 先看事实,再选检查深度。** 在写正式实现判据、派实现或主 agent 自己实现之前,
用 proposal 的用户原话和 design 里的行为变化判断;探索性的最小探针可以先做。

| 观察到的事实 | 下一步 |
|---|---|
| 沿用已有契约,证据足够,局部可逆的修改(如错字、已复现且修法明确的窄修复) | 主 agent 直接做相应验证;不为此起规划腿或填一张大表 |
| 成败依赖未验证事实(性能、运行环境、外部服务、兼容性等) | 先做能推翻该前提的最小探针;未知不能写成已验证 |
| 新增/改变用户必经步骤、默认自动动作或失败退路;改变数据/权限/跨模块契约;或选错需迁移、协调多个模块/部署目标才能撤回 | **至少一次不同于主 agent 家族的独立方案挑战**,即使需求清楚或自报 low;有关键未知还须实验 |
| 有几个实质不同的方向,或挑战暴露目标冲突/尚未解决的关键分歧 | 独立双出或 panel-explore,比较取舍后收敛;不靠多数票 |

各行可同时命中,轻量路径不能覆盖后面的触发事实。按行为/契约判断,不是按文件数、
impact 档或文件名判断:一个默认值也能改变整条路径;纯测试/工作流文件也可能改变验收契约。
**同一类问题第二次打补丁**时重新检查根因和设计;修改契约或方向时按上表走,不是自动全池。

**② 独立输入与有界花费。** 主 agent 先把自己的方向与最危险前提落盘,但不喂给独立腿。
brief 给用户原话、当前行为及证据、约束、拟改变的行为;区分用户要求与 agent 的推导,
不塞主 agent 的结论、Jev 分数、先前报告或「方向已定」。要求独立腿先从目标推演失败场景,
再挑战拟议行为;需要核实仓库时必须选能读取相关实现/调用方的腿,
禁止读取本轮自审和同伴报告。只读挂载不等于机械阻止读取自审,仍须核查实际输入和读取记录。

题面只需问三件事:完全实现仍怎样失败?哪个前提若为假就要重做?有无更简单的方向,
用什么最小实验分辨?不强制凑问题,不让它只核对规格条款。
需要读代码的单次挑战先查 `panel-candidates --mode explore`,选择能读仓库的不同家族成员,
用 `panel-explore --members ID BRIEF REPO PREFIX` 只派该成员;
仅当 brief 已含必要事实/相关片段、无需查仓库时,可选 `submimo`:
它**禁止工具、只读题面**,不能把给了仓库路径当成已经核查源码。上下文不足先补事实或换有能力的腿,
不能据此宣布检查完成。先核对实际模型家族;这不是新增 review 模式,不要求 PASS/BLOCK。初始只派一条外部腿,
有具体未解分歧再追加一条。真实方向分叉时可用 panel-explore 明确选择多个成员;旧入口不带 --members 会派默认启用的多条腿。派发前说明本次范围/调用上限,失败重试照记,不默认全池。
模型不可用时可以继续收集事实,但不能把失败调用算成完成挑战;仍有触发事实的实现先不推进。

**③ 核实后才定方案。** 在 design/evidence 留:被挑战的行为与前提、原始意见及出处、
核实结果/实验、取舍理由、未解决项。能改变方向的未知先解决或选不依赖它的方案;
涉及用户目标冲突才向用户澄清,例行推进无需逐步审批。模型没发现问题不是前提已验证。
方案定下后,主 agent 再写实现判据;正式实现仍按现有 oracle 先行和收货规矩执行。
目标、关键行为或支撑证据实质改变时重看受影响前提,不复用旧意见宣布新方案已检查。

两轴与机器契约保持不变:`impact-risk` 决定实现评审预算;`design-uncertainty` 是检查后的判断,
不拿 high impact 当全池规划开关,也不拿 low 当免检凭据。实际完成前提检查后,
沿用 `premise_attack.status=done` + 持久 `evidence` 引用,low 也可为 done;
轻量路径仍允许 low + not_required。`done` 记录检查做过,不证明所有前提成立,
也不能放行上面尚未解决的关键问题。机器只查结构/证据存在,不声称理解理由。
设计意见不替代实现评审或归档覆盖;委托前的 oracle 攻击另问「坏实现能否骗过考卷」,
不能拿它替代这里的目标/方案挑战。

**④ Jev 只提醒。** `triage --track <目录>` 可在主 agent 拍板前提示遗漏前提;
它只看到所给文字。高分回到事实核实,低分、next_step=implement 或没有触发阈值都不能
取消上述检查、降低 impact/uncertainty、筛掉 finding 或决定收货。概率不是准确率,
同一批例子调题后的报警率不是误报率。检索历史案例的排序可另做旁路实验,本协议不自动接入。
Jev 不进入 oracle/权限/归档闸,不可用时回到主 agent 判断,不绕开原有检查。

这是 agent 必须执行的决策协议,不是新增语义机器闸。先观察约五个自然任务:
在 design/verify 简记触发事实、前置调用/耗时、改变了哪项决定及核实证据、后续设计返工;
没有的数据写 unknown。只多填表、没有改变证据或决策的步骤应缩减,不凭小样本宣称提效。

### 5. 单腿回落
某个后端不可用(key 过期等)时只跑一条也行,但要注明是谁跑的。
**主 agent 自己的第一遍审,永远不是可选项。**

## panel-explore — 发散,panel-review 的孪生兄弟

用在**方向尚未收敛**的开放设计问题上(也可以是已有实现需要重新选方向):几个不同模型家族各自独立回答**同一份 brief**,各提
**一个**具体方向(Direction / Core bet / How it works / Best at / Sacrifices / Blind spots
in the brief / Smallest first step)。**故意没有裁决——分歧的铺开本身就是产出。**

`panel-explore BRIEF_FILE [REPO_DIR] [LOG_PREFIX]`,同样只派发不决策。
默认派 MiMo、DeepSeek、GLM、Grok 和 Cursor；`PANEL_GROK_LEG=off` / `PANEL_CURSOR_LEG=off` 分别关闭对应通道。
Grok 的 review/explore 共用 `bin/grok-model`，升级模型只改这一个配置文件。
Cursor 的两种模式同样共用 `bin/cursor-model`；`CURSOR_MODEL` 可单次覆盖，家族随所选模型变化。

同样的反锚定纪律:**主 agent 先把自己的方向写下来**,再把各份报告读作角度扩展 + 盲点网,然后
**综合**。不要把分歧塌缩成一个答案,不要平均成假共识,不要让多份浅见洗成"很全面"。
**brief 要写得更精简**——过度规定"好答案应该覆盖哪些点",模型就会锚定、不再发散。

brief 放 `/root/aiwork/tasks/`,日志放 `/root/aiwork/logs/`。两个 `panel-*` 工具都做了
启动错峰,共享引擎对 429/5xx 有带上限的退避,并行扇出不会再静默丢腿。

## panel-slice — 切片评审(试点,2026-09-13 起)

一份改动切成 2..8 片,**每片一次会话、一个不同家族的腿**,外加一条独立整体腿(默认
`subcodex` = GPT,家族不与任何片重复)。N 片 = **恰好** N+1 次会话,腿里不再派子 agent;
每项都是一次钉住单腿的 `panel-review --scoped-review`,反锚定闸/任务冻结/抗断线全部照旧。

```
panel-slice run [--require-my-review PATH | --no-my-review] MANIFEST [REPO] [RUN_DIR]
panel-slice status RUN_DIR [--json]                 # 纯读盘重建
panel-slice verify RUN_DIR VERIFY_MANIFEST          # 登记 finding + 换家族定点复核(占 extra)
panel-slice retry  RUN_DIR ITEM [--leg LEG]         # 重派一项(每次都占 extra,done 的也算)
panel-slice abandon RUN_DIR ITEM#N --reason …       # 永远等不到终态的 unknown 尝试(有活进程引用就拒)
panel-slice decide RUN_DIR FINDING confirmed|rejected|accepted-risk|inconclusive --reason …
```

- **什么时候用**:改动大到「每条腿全量看一遍」注意力被摊薄,而且我说得清切片边界。
  小改动、切不开的改动,照旧 panel-review。
- **不能替代归档门槛**:切片结果 `review_contract_version=2`,**永不**计入任何 track 的
  self/standard/high 覆盖,`panel-slice` 也拒绝绑 track。要归档资格照旧跑 panel-review。
- 切片在实现后集中审查注意力,不能补做 4c 的方案检查,也不因 Jev 分数自动启用或删片。
  试点是额外成本,不能默认所有大改动都全量+切片双跑,更不能宣称已经省时。
- 最大的盲点是**责任范围遗漏**:主 agent 派发前逐项把完整变更清单对应到行为切片,
  并列出未修改但受影响的调用方、老测试、构建/部署脚本及跨片契约的负责人。
  各片可读完整仓库;整体腿先从原始目标独立看全局,不能只检查切片摘要。
  整体腿也会漏:09-16 片外老红检只被全量 DeepSeek 抓到,不是再加一个整体 PASS 就有保证。
- 各腿须审同一份冻结输入;评审期间不要往源仓写 observation 等新文件。
  `status` 报 source mismatch 就是未完成,不能手工忽略成通过;当前工具只检测,不替你冻结共同源。
- `run_state=clean` 只是事实汇总(都收齐了、BLOCK 都登记并处置了),**不是 PASS**。
- 登记 finding 的 `source` 写**哪一次尝试**(`dispatch#1`、`overall#2`),不是只写项名:
  一条 finding 只确认那一次的 BLOCK/NMI,同一项两次 BLOCK 要登记两条。
- 审 aiwork 自己时:RUN_DIR 默认在 `logs/`(仓内,会被拒),自审默认在 `tasks/`(同样仓内)——
  两个都显式给仓外路径。
- 清单格式/分配/预算/状态语义:`panel-slice --help`;为什么这么设计、各腿「不许派子 agent」
  逐腿核实表:track `sliced-panel-review` 的 design.md;GPT 腿细节:legs.md 的 subcodex 一节。

## 信任校准(反复被验证的三条)

- panel 是**盲点网**,不是裁决机。
- **孤腿 BLOCK 才是信号**(3 家 PASS + 1 家 BLOCK 且成立,发生过)。
