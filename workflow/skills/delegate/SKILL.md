# delegate — 派活给执行腿

**第一性:judgment 集中在规格与验收,不在打字。** 写 plan/oracle/审/裁需要 frontier 脑;
照着一份红的 oracle 把实现写绿,不需要。

## 谁负责什么(不可外包的部分)

**主 agent 永远负责**:plan、task brief、**oracle(亲自写,永不外包)**、双轴决策、
验证、仲裁、merge/push/归档。

**这条是铁律,和评审那边同源**:oracle 永远由主 agent 编写和拥有,**绝不能由执行腿写**。
弱模型最可能的失败方式,就是**改考卷让自己及格**(删断言、把期望值写死、加 skip)。

## 选哪一档

| 情况 | 派给谁 |
|---|---|
| 小而明显的活 | **主 agent 直接干**(切碎反而更贵) |
| 1-3 个文件的小修、测试、lint/类型修复 | **`submimo fix`**(微档,见下) |
| PR 级实现 | **codex 腿 `-m gpt-5.5`**(默认档) |
| 架构敏感 / 跨模块判断 | 升 **`gpt-5.6-sol`** |
| **考卷需要开网络端口** | GPT 照派,**主 agent 当测试机**(有界 2 轮);或给 Claude 腿。见下"网络"一节 |
| 需求不清 / 大架构没定 | **先 plan 或 panel-explore,不派活** |
| ~~整单丢给 fork(后台分身)~~ | **不是一档,别这么派**(见下) |

**⚠️ fork(后台分身)不是执行腿的任何一档**(2026-08-08 实证,track
`opendesign-owner-review-0808`)。执行腿的形状是**窄口子 + 交活给老板验**:
给一段任务书、限定文件范围、oracle 上锁,回来一份 diff 过三道闸。
fork 的形状是**带着老板的全部上下文和老板的自我认知** —— 派整单给它,它会
自己写 oracle、自己实现、自己跑判据、自己开 panel、自己下裁决:
**三道闸全都搬进黑箱由被查方自己执行**,工件链看着一条不缺,每一条却都是自述。
那天的两个实测症状:① 判据与实现同一个 agent 写(=最经典的"改考卷让自己及格"结构,
只能靠主 agent 事后做**变异测试**补救);② 主 agent 在同一个仓库里做变异测试时,
fork 把它判成"评审腿篡改",恢复了文件并 kill 掉主 agent 的判据进程 ——
**两个都自认"唯一控制者"的 agent 会互相执法**。
要用 fork 就只派**可外包的那一半**(实现、跑判据、调 panel),
并在派活时明写:不下裁决、不 bump、不归档,原始证据交回来。

**为什么执行档可以随便换、评审档不行**:把关的是考卷 + 三道闸,两者都与模型无关;
换执行腿动的只是返工率和额度。而**四条评审腿里没有 GPT**,所以 GPT 同时管规划和执行
也当不成自己的裁判。

**分层的理由是额度**:GPT 走 ChatGPT 订阅,Claude 额度全留给规划/判卷/仲裁。

**Sonnet 档留作后备**(2026-07-18 4 单试跑返工率≈0,是唯一有样本的档)。

**GPT 档:2026-08-04 现状 —— 已跑 7 单,但这本账烂了,不能拿它定型。**
08-04 体检实查:记忆里的计数停在"样本 2、还欠 1 单";两个不同的 track 都自称"第 3 单";
我凭印象报给用户的返工率表**和工件对不上**(工件里没有任何一单是 2 轮返工)。
一本互相打架的账做不了"定型 / 删 Sonnet 档"的依据。
⇒ 不再手工维护“第 N 单 / 返工 N 轮 / 自身错误 N 处”。计划决策只写 track 的
`decision.json`；controller 实际 dispatch、rc、耗时和真实可得 usage 写紧凑 observation，
由只读 ledger 当场汇总。拿不到就是 null，不能把订阅额度或现金费用猜成 0。旧 track
明确标 legacy/unknown，不从 `verify.md` 自由文本回填。

## 规划:先检查方案,再决定是否双出

按 **panel skill 4c** 判断,不是按「我要不要外包」判断;主 agent 自己实现也一样。
新增关键行为、改变契约或选错后难以撤回的方案,先由不同家族从用户原话独立挑战,
关键未知先实验;有真实方向分叉才扩大为独立双出/panel-explore。沿用已验证契约的局部修改保持轻量。
先落主 agent 的方向,不把自审/结论喂给独立腿;核实与取舍留在 design/evidence。
**「方向已定」必须来自这次检查,不能因为用户需求清楚、自己填 low 或 Jev 低分就跳过。**
委托前 `--attack-log` 的 oracle 攻击仍要做:它问考卷能否被坏实现骗过,不能顶替目标/方案检查。

## 流水线(PR 级 track)

1. 先完成上面的设计检查,再 **oracle 先行,且先 commit 进 main 再开 worktree**(让执行腿从基线继承,别让它自己往里
   copy)。**oracle 必须先红检**——没红过的 oracle 不算 oracle。
2. **派活 prompt 必带三件**:
   ① oracle 逐字节 off-limits;② 自检清单(oracle + 回归 + build 全绿才交);
   ③ 不 push / 不 merge / 不归档。
   **2026-07-26 起这三件更重要了**:执行腿(尤其 codex 腿)**看不到本机说明书**,
   规矩不写进任务书就等于不存在。
3. **收货三道硬闸——执行腿的自述一概不作数**:
   - ① **oracle byte-diff**:对 oracle 原始 commit 逐字节 diff,必须为空(或逐行核明的
     最小 harness 修复,如补 import)。worktree 基线一旦落后 oracle commit,**这道闸是唯一
     防"改考卷"的东西,每次必走**。
     **同时查 `git status --porcelain -- <判卷路径>` 也为空**:`git diff <commit> -- tests/`
     **看不见新增的未跟踪文件**,塞一个 `conftest.py`(autouse fixture)就能让闸②"亲跑
     全绿"变假绿,而闸③亲读 diff 也照不到它(它不在 diff 里)。08-04 临时仓实测。
   - ② 主 agent **亲跑** oracle + 回归 + build。
   - ③ **亲读 diff**(安全面逐行)。顺带盯 `create mode 120000`——执行腿在 worktree 建的
     符号链接被 merge 带回主仓会**覆盖掉真目录**(出过事故;`.gitignore` 带尾斜杠只匹配
     目录,挡不住链接)。
4. **`decision.json` 的 `impact-risk` 硬规矩:新写口/权限/auth/钱/数据一致性面 = high，针孔再薄
   也不打折。** 默认预算 self=0、standard=1、high=2；high 取两条健康跨家族腿，失败/
   降级/冲突才追加。判卷、沙箱、权限控制面才显式 `panel-review --all`。
   `design-uncertainty` 按 panel 4c 检查后另判 low/high,不拿人数或自报 low 代替方案检查。
   切记 **oracle 是主 agent 写的、可能本身就错**——过审只证明"合乎规格",不证明规格对。
   (07-18 实锤:错误编码进 oracle,当时的单腿评审对着错考卷判 PASS,双漏。)
5. 主 agent 仲裁 → 修(自己或回派)→ merge → e2e → push → 归档。

## submimo fix — 微档

`submimo fix TASK LOG REPO`,**仅限有界的实现任务**:

- 任务文件必须写明**允许改动的文件**或一个窄模块范围。
- 适合:小 bug 修复、测试、lint/类型修复、说明清楚的 1-3 文件改动。
- 跑完必须查 `git diff`、跑相关检查,**最终判断留在主 agent**。
- **尽量给一个客观的通过/失败 oracle**(test / lint / typecheck 命令)。目标行为若没有测试
  覆盖,**主 agent 先自己写一个聚焦的回归/特征测试并 commit**,再对着它派 fix 循环。
- **重试封顶**:oracle 连红约 2 次就收回主 agent,不要死循环。这个循环已内建且 DEFAULT-ON:
  `--oracle CMD` 每次尝试后跑 CMD,绿了退出 0,红了重试(上限 2),然后非零交还,并归档每次
  尝试的 `git diff`。
- **`submimo fix` 在既没有 `--oracle` 也没有 `--no-oracle` 时会拒绝运行**——忘了检查会让
  工具罢工,而不是悄悄退化成裸跑一发;`--no-oracle` 是清醒的显式退出。
- **`--protect PATH`(可重复)**:每次尝试对判卷文件做哈希校验,**一有改动就硬失败(exit 3)**
  ——这是上面 off-limits 规矩的机械版。**硬要求:oracle 为得出裁决所读的每一个文件**
  (测试文件、fixture、期望输出文件)**都必须列进 `--protect`**;守卫的强度只等于这份清单,
  漏列一个判卷文件,就正好是"改考卷让自己过"的那个洞。

**不要默认动用 submimo 的场合**:极小且明显的编辑;纯解释或头脑风暴;需求不清的任务;
没有事先 plan 的大范围重构/架构改动。

**安全边界(所有外部执行腿通用)**:不许 push、merge、删文件、装依赖、碰生产系统、
跑数据库迁移、改密钥。需要危险操作时**先问用户**。
task 存 `/root/aiwork/tasks/`,log 存 `/root/aiwork/logs/`。
外部腿的输出是**待评估的证据**,不是自动生效的决定。

## codex (GPT) 执行腿 — 2026-07-26 起

用户拍板:**Codex 是主 agent 调用的员工,用户不再自己开 Codex 会话**。
动机是额度——GPT 干实现,Claude 的额度省给规划/审/裁。详见 [[codex-as-employee]] 记忆。

**派活走入口 `bin/delegate-codex`,别再手敲 `codex exec`**(2026-08-06 起):

```
# ① 攻完题,先把这一行盖进攻题记录(2026-08-11 起没有它派不出去)
delegate-codex --print-oracle-hash --repo <仓> --protect <判卷路径> ... >> <攻题记录>
# ② 派活(缺攻题记录 / 缺判卷清单 / 哈希对不上 就拒发,codex 一次都不启动)
#    **默认在独立 worktree 里跑**;要回老行为(腿直接写主工作树)才加 --no-isolate
#    仓里有开着的 track 时,**必须亲口说这单归谁**:--track <轮次名> 或 --no-track
delegate-codex --task <任务书> --repo <仓> --attack-log <仓外的攻题记录> \
               --protect <判卷路径> [--protect ...] [--model gpt-5.5] \
               (--track <轮次名> | --no-track) [--no-isolate]
# ③ 收货闸①(机械版:四条臂跑在那棵树上,并顺带查主树有没有没提交的判卷动静)
delegate-codex --receive <回执.json>
# 只读评审仍直接调 codex(见 panel skill)
codex exec -C <repo> -m gpt-5.6-sol -s read-only \
           -c project_doc_max_bytes=0 -o <log> "评审任务书"
```

`--track` 不是目录标签而已：入口会在建 worktree / 启动 Codex **之前**对主仓里的
`tracks/<轮次>/decision.json` 跑 dispatch 校验；从 attached worktree 发起也仍以主仓卷宗为准。
Codex 退出后，仓外 receipt 先补齐 `run_id/started_at/finished_at/duration_ms/codex_rc`，再只把这些
白名单字段导入主仓 `observations/`，写成 `execution_finished`；`--receive` 跑完闸①后另写
`received`，两件事不互相冒充。观测不含 task、attack log、protect 清单、log 路径或 transcript；
订阅拿不到 token/API 现金成本时就是 `null`。导入失败会明确打印 `OBSERVATION_WRITE_FAILED`，
但绝不能覆盖 Codex 或收货闸原本的 rc。`--no-track` 和 `--dry-run` 都不伪造事件。

**默认隔离(2026-08-11,track codex-worktree-delegation)**:每单一棵
`/root/aiwork/worktrees/<任务名>-<时间戳>` + 一个 `delegate/<同名>` 分支,从派活时的 HEAD 建。
买到的是**归因**:闸① 的基线是派活时 HEAD,而"腿说考卷错了 ⇒ 我改考卷并提交"是常规路径 ——
同一棵树上那些提交会让闸① **判红在我自己头上**,而误报的守卫活不过一周。
收货通过后它**只打印**集成 / `create mode 120000` 自查 / `worktree remove` 命令,
**不自动 merge、不自动删**(自动删的代价是丢掉唯一一份改动)。

**归属与回收(2026-08-12,track worktree-sweep)**:`--track` 把轮次写进树的路径
(`worktrees/<轮次>/<job>`)和分支名。**归档那一轮时(`track archive`),挂在它名下的树会被
自动收掉** —— 但只收**确认干净的**:①工作区没有没保存的东西 ②它的提交已经进了主线。
任一条不成立就**拦住归档**并点名(`--keep-trees` 显式放行)。别人的轮次、无主的树
**一律只点名不碰**(要收自己去查了再敲)。
所以:**忘了传 `--track` 的代价是这棵树以后没人自动收** —— 也正因如此,仓里有开着的 track 时
入口会**拒发**,逼你说一句(不替你猜:把"我没说"翻译成"我同意删"是删那一侧的风险)。
观测写在主仓 track 而不是执行 worktree，所以安全 sweep 只回收冗余执行现场，不会把成本—质量
事实一起删掉；完整日志/receipt 仍按各自 retention 处理，ledger 不依赖它们。

三条实测出来的边界,别凭推理:

- **隔离不是沙箱边界。** `-s workspace-write` 的可写范围是它自己向上解析出的"项目根" ——
  worktree 的 `.git` 是文件,于是它一路走到**主仓**,能往主仓写;`/tmp` 也敞;读完全不管。
  所以卷宗(攻题记录/日志/回执)仍然**不许落进「仓 ∪ worktree 根」**;
  **派 `/root/aiwork` 自己的活时,`/root/aiwork/logs/` 也在禁区里**,要显式 `--log` 到仓外。
- **判卷路径必须先 commit 干净**才派得出去(树从基线建,腿看到的是已提交那版)。
- 直通参数里带 `-C`/`-s` 会 last-wins 撤销隔离 ⇒ 隔离下直接拒发。

入口替你做三件本来靠"记得"的事:**逐字注入派活三件套**、
**把判卷清单和派活时的 HEAD 存进回执**(收货用同一份,不再人眼重建)、
**每次都带 `-c project_doc_max_bytes=0`**(否则 codex 自动吞被派仓库里的 `AGENTS.md`
并向上层递归找;本机说明书已改名规避,但别的仓库可能自带一份)。

**派活前先攻自己的题** —— 这是入口的必填项 `--attack-log`,不是建议:
拿现在这版 design + oracle 请第三方(`codex exec ... -s read-only` 或 panel 腿)攻一遍
「哪条断言全绿了结果仍然错」,记录落**仓外**(进了仓 = 把考卷的洞递给考生)。
入口还会查这份记录**对不对得上这一版判卷**:攻完之后又改了 oracle,那份记录就过期了,拒发。
判的是**内容哈希**不是 mtime(2026-08-11 换的:worktree 是 checkout 出来的,mtime 恒新 ⇒
旧闸在隔离下 100% 拒发,而绕它的唯一办法是每次 `touch` 攻题记录 = 把"例行解除一道判卷防线"
变成肌肉记忆)。所以攻完题要跑一次 `--print-oracle-hash` 把那一行盖进去;
**改了判据就得重来一遍**(这正是它要问的事)。
> 08-05 实测:一单里五个真实缺陷**至少四个不看实现就能发现**,却全都等到执行腿跑完
> 22 分钟 + 主 agent 收货 53 分钟之后才被抓。用户给这形状起过名字:
> **有能力的检查站在成本花掉之后。**

**判据先红检,而且要"退回红检"**:`redcheck --base <基线> --impl <实现路径> --oracle '<判据命令>'
[--build '<build 命令>'] [--must-fail '<目标失败标记>']`。它把实现真退回基线再 build 再跑判据,
**要求红**;旧实现下仍绿 = 有恒真断言,先修判据别派活;build 没过 = 这次红检不算数。
> 08-05 实证:手写桩红检 ⇒ 恒真前置是绿的,洞没露出来;真退回 build ⇒ 当场抓到。
> **桩红不算数。**

- **模型要显式给 `-m`**:执行 `gpt-5.5`,架构敏感升 `gpt-5.6-sol`。
  `~/.codex/config.toml` 里的默认值是 `gpt-5.6-sol`,**别依赖它**——依赖默认值就等于
  以后改了配置这里会静默升档。`model_reasoning_effort=high`,可按活的难度调低省额度。
- **要求它用中文回答**,否则默认英文。
- **它看不到本机说明书**(说明书叫 `CLAUDE.md`,Codex 只认 `AGENTS.md`),所以
  **派活三件套必须逐字写进任务书** —— 走 `delegate-codex` 时它自动注入。
- 收货三道硬闸照走,一道都不能省:闸① 用 `--receive`(它顺带列出执行腿动过的**全部**
  文件,含未跟踪的,给闸③当底账,并把这份写集写回回执);闸② 主 agent 亲跑;闸③ 亲读 diff。
  **闸② 要在哪棵树上跑**:腿的活在 worktree 里,合回主仓之后**必须再跑一遍**——
  worktree 里的绿不许复用(集成后组合才是新的待验证对象)。
- **入口防的是"忘了",不是"故意"**:`codex exec` 永远还在,绕过是一行命令的事。
  别把它当安全边界。

### 网络:保持关闭,考卷要开端口就换 Claude 腿

沙箱默认禁网,所以**需要开本地端口的考卷它跑不了**(会交一份自己没验证过的活)。
**不要为此开网络开关** —— 它是布尔的,没有"只放 127.0.0.1"这一档,为一个本地端口
付的是全网出口的代价:

1. **能装依赖了** —— "不许装依赖"从物理保障退化成靠自觉,而装进来的第三方代码
   会在本机执行,不在我读的 diff 里;
2. **能摸到环回上的本机服务**(gateway、ds-web),这些服务的前提是"只有本人连得上";
3. **无痕泄漏** —— 机器上有凭证(`kimi-review-home/credentials`、`~/.codex`),
   风险不是它想干坏事,而是提示注入把它带跑,而**闸③读 diff 看不见发出去的东西**;
4. 测试的"绿"不再可复现。

**解法是换腿或换分工,都不是拆墙**。真要开也**只在那一条命令上临时开,绝不写进
config.toml**(写进去=以后每单都开着)。
