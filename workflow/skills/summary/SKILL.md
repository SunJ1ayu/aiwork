# summary — 一轮评审的汇总

评审与修复规则见 [REVIEW-RULES.md](https://github.com/SunJ1ayu/aiwork/blob/main/REVIEW-RULES.md)，项目已接受风险见项目 main 的
`.aiwork/accepted-risks.md`，放行条件见项目关卡策略。这里只说汇总这一步怎么做。

汇总是流程里固定的一步，不是谁的习惯：现在由业主派的一个独立会话做，以后由 OpenClaw 叫醒一个能读代码、跑测试的强模型来做，做法都按这份。

## 什么时候做

一轮什么时候开始，见 REVIEW-RULES 开头的定义。各条腿只审当前这一版；跨轮次、跨各家的判断都在这一步做。

## 读什么

- 当前 head 上各家的评审；
- 派腿一方写在 PR 说明里的各腿结果表，失败的腿和原因从这里读；
- 这个 PR 前几轮的汇总（发在 PR 上）；
- PR 说明里修改方逐条写的处理；
- 业主在 issue 和 PR 里写下的决定。只在对话里说过、没写下来的，不算。

这是第几轮、到没到上限，见 REVIEW-RULES。

## 怎么做

1. 去重：同一处问题合成一条，注明哪几家提的。
2. 核实：在断网的隔离副本里跑全套测试；每条 P1 照描述复现。算不算 P1、复现不了还说不清时怎么办，见 REVIEW-RULES，这里不另定。抽查新测试在修之前的代码上是红的；要真机才能确认的，标成待业主确认。
3. 定级：按 REVIEW-RULES 第二节，分清本 PR 新引入的和原来就有的。
4. 决定下一步：按 REVIEW-RULES 第三节的优先顺序。要派修改单时，用 delegate 的「PR 任务单」；P2 放不放进这张单，见同一节。
5. 发到 PR 上：用汇总者自己的 GitHub 账号发一条 COMMENT 评审，不用项目策略里的 `reviewer_bot`（没有结论块的机器人评审，关卡会算成 BLOCK）。关卡不读汇总。合不合由业主看了汇总以后批准、贴标签决定。汇总不批准、不贴合并标签、不推代码。

## 汇总的格式

- 标题：独立审核 · head <短提交号> · 第 N 轮
- 这一轮做对了什么；核实了什么（跑了什么、结果如何）；各家结果（谁 PASS、谁 BLOCK、谁失败及原因）；
- 每条 P1：要写的项见 REVIEW-RULES 第二节第 2 条，再补哪家提的、要求怎么改（只写要求和位置，不写代码形状）；
- P2、P3；
- 刹车：这是第几轮，到没到上限见 REVIEW-RULES；
- 「评审的处理」表：来源 | 处理；
- 最后一行：Conclusion: PASS 或 Conclusion: BLOCK。
- 下面一行，三选一：下一步：合并 / 照单修 / 交业主（先不派）。按 REVIEW-RULES 第三节的优先顺序选。
