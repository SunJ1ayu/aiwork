# 评审交接入口

`bin/review-auto-worker CONTEXT SETTINGS` 接收公开交接事实，调用本机配置指向的仓库正式评审入口。事件中的 argv、链接和说明不作为命令运行。

SETTINGS 是仓库外、权限 600 的 JSON 文件，父目录权限 700。必填 checkout（评审源码检出绝对路径）、programs（程序登记目录绝对路径）、repository（目标仓库）、event_source（中台来源名称）；可选 concurrency（同时运行的轮数）、timeout_seconds（每轮从预检到收尾的总时限，秒）。可选项的兜底值和校验只在 [交接入口的 LOCAL_DEFAULTS 与 load_settings](../bin/review-auto-worker) 定义。缺项用兜底；未知字段、非正整数、布尔值、坏文件或读不了设置均拒跑，不增加并发。改本机设置无需开 PR；排队者每次申请容量都重新读取 concurrency，调小后等已有轮次退出才接纳新轮。不得提交实际配置、身份、密钥或运行记录。

容量按评审机数据根目录协调，各仓库共用容量。满了等待；同一仓库同一 PR 的请求先排队，避免重复请求占满容量。每轮从配置的源码检出克隆独立 Git 仓库，再从其 origin 拉 main；不切换源码检出，也不共享工作树、索引或对象硬链接。正式入口仍检查最新 main、当前 head、项目策略和当前 head 的 CI。

每轮在独立的 Linux 进程、挂载命名空间中执行，保持现有评审腿隔离不变；需要评审发布账号已有的命名空间能力。总时限到期结束本轮全部后代（包括新建会话的 CLI），释放容量，不自动重跑模型。父交接进程中断时，子进程继续持有继承的容量/请求锁直至退出，不能提前重复接纳。无法创建命名空间时拒跑，不退回无隔离执行。

去重和恢复记录在 [数据目录登记表](../bin/_aiwork_config.py) 的 `review-handoffs` 项；不按日志保留期删除锁或成功记录。原子换名、文件与目录同步保证最终路径不出现半截新记录。成功记录阻止同一 head 再派；失败、中断和损坏记录允许恢复，原始记录保存在本次尝试目录。各次尝试（独立检出、脱敏日志、前次记录和结果）各占 `tasks` 的一个第一层单位，分别计龄清理。正式派发仍由 `review-pr --auto` 核对已存在的评审，不自动整轮重试。

升级时先停止旧入口接单、等旧进程退出，再启用新入口；保持原来的 repository 和数据根目录。旧版没有记录仓库身份：程序只在原配置所指仓库下读取旧 `tasks/review-auto-handoffs` 的同 PR/head 成功记录，受旧锁保护，转存到持久记录后阻止重复；未成功或损坏的旧记录保留为本次证据。确认转存前不要清理旧记录或将该配置改指另一仓库。新安装没有旧记录时无需迁移。

交接自身只对 Git 操作使用 [retry](../bin/review-auto-worker) 定义的有限重试；GitHub 读取沿用 [正式入口](../bin/review-pr) 及其调用的读取器的重试，不再套一层。文档不另定次数。记录失败留本机，回执只给公开事实或已脱敏失败。

评审接收、验证、去重和收尾逻辑在仓库；中台路由、服务安装、配置与机器间传输留本机。其他本机适配器不因此自动收入仓库。

合并后，操作员将中台固定启动命令改为本入口并传入 context 与设置文件；评审机安装设置并核对源码检出、程序路径和事件来源。不得把事件中的命令直接执行。先在目标环境验收，再替换旧入口；本 PR 不部署机器。并行与内存验收见 [Linux 评审机验收](linux-vm.md#评审交接并行验收)。
